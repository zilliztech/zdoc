# REST 参考页参数级可见性：GA/Public 徽章 + next/current 控制

## Context

两个 UAT 验证会话（PR #1254/#1258）暴露了同一类问题：zilliz REST 参考页是 latest-only 渲染，3.0-only 参数（`fields/drop` 四参数、顶层 `externalSource/externalSpec` 等，片段里已有 199 处 property 级 `x-added-at: 3.0.x`）与 GA 参数混排且无任何版本指示，2.6 GA 集群用户照页面调用会 404/静默失败。同时 `CUSTOM_ATTRIBUTES.md` §1.12 已声明参数级 `x-next-channel`（next/current 暂存），但实现停留在 "registry-only for now… until per-field rendering lands"——本次把两个参数级可见性机制一次性落地：

- **PR 1（徽章）**：参数级 GA / Public Preview 标签。数据零标注成本——从既有 `x-added-at` 派生 + 显式覆盖字段。
- **PR 2（next/current）**：参数级 `x-next-channel` 真正渲染——运行时按部署 channel 显隐。

关键架构事实（已核实）：REST 页 MDX 只嵌 `export const specs = {...}`，参数渲染 100% 在运行时 `packages/docs-ui/src/shared/components/RestSpecs/index.js`；部署 channel 是运行时注入（`window.__ZDOC_ENV__.RELEASE_CHANNEL`，同一构建服务 current/next，`packages/docs-ui/src/shared/utils/releaseChannel.ts` 的 `useRuntimeReleaseChannel()` hydration-safe、未知值 fail-closed 回落 current）；refGen 对 specs JSON 原样透传（`refGen.js:353`），页面级徽章链路 `x-beta → frontmatter → DocTag("Public Preview"/公测版)` 已存在。

## PR 1 — 参数级 GA/Public Preview 徽章

### 数据模型

新扩展 **`x-zilliz-availability`**（string，值域复用 `availability/zillizPriors.js:14` 词表：`GA | PUBLIC_PREVIEW | PRIVATE_PREVIEW | ON_REQUEST | NOT_AVAILABLE`；**缺席 = GA，fail-open**，同 `x-zilliz-cluster-types` 惯例）。refGen 构建期物化进 specs JSON（运行时保持"傻"）：

```
effective(node) = node["x-zilliz-availability"]        // 显式覆盖优先
               : node["x-added-at"] >= "3.0.x"          // 派生（releaseTrack.js 数值比较，非字符串相等）
               : undefined
```

噪音抑制规则：页面级 `beta_tag` 已解析为预览档（PUBLIC/ON REQUEST 等，非 FALSE/DEPRECATED）时跳过参数物化——页面标题徽章已表达，不逐参数重复。

### 改动文件

1. **`packages/docs-tooling/src/reference/rest/refGen.js`**
   - `validateSpec`（72-106）：扩展递归校验器覆盖 `x-zilliz-availability`——值域白名单、非法值 throw（fail-closed，对齐 `validateI18n` 模式）。

## PR 2 — 参数级 next/current 控制（顺序在 PR 1 合并后）

### 语义（逐字对齐页面级 §1.12）

| 参数标记 | CURRENT 部署（含 unknown/缺失，fail-closed） | NEXT 部署 |
|---|---|---|
| `x-next-channel: "include"` | 隐藏 | 显示（页面 NextChannelToast 已有横幅，参数不加额外 chip） |
| `x-next-channel: "exclude"` | 显示（终版措辞） | 移除 |
| 无标记 | 显示 | 显示 |

required chip 随参数隐藏自动消失；写侧约定 include+exclude 成对翻转（keepWarm `cron→daysOfWeek` 形状）。milvus.io 部署无 RELEASE_CHANNEL 注入 → 运行时恒 current → 未发布参数在那里同样隐藏（fail-closed，符合"未发布内容不可见"）。

### 改动文件

1. **`refGen.js`**：`validateSpec` 扩展 `x-next-channel` 值域（`include|exclude`，与 `resolveNextChannel`（37-41）同严格度）。**透传零改动**（已原样进 specs JSON）。
2. **`RestSpecs/index.js`**：引入 `useRuntimeReleaseChannel()`；helper `paramVisibleInChannel(node, channel)`；应用到两处既有过滤点——RestSpecs 主组件 parameters 过滤（~796，现有 `x-include-target` 过滤旁）与 `Properties` property 过滤（162-163）。Items/AnyOf 经递归进入 Properties 天然覆盖；anyOf **分支级**标记本轮不做（记录限制）。
3. **`CUSTOM_ATTRIBUTES.md` §1.12**："registry-only" 段替换为已实现行为表（保留该节被 `customAttributes.contract.test.js` 锁定的语句：scope 句、include/exclude 值表措辞按原文保留，仅改状态描述），补 milvus target fail-closed 说明。
4. **测试**：`RestSpecs/index.test.tsx` 增加 channel 用例（jsdom mock `window.__ZDOC_ENV__.RELEASE_CHANNEL`：next/current/未知值回落 current；与 `x-include-target` 过滤叠加；无 window（SSR）=current）；`refGen.availability.test.js`（或独立小文件）加值域校验用例。

### 首个使用方

## 顺序与风险

- PR 1 → 合并 → PR 2（两者都改 RestSpecs，串行不并行）。
- `resolveRefs` 共享引用 → 逐页深拷贝必须在 admonition 注入前完成（PR 1 内完成，PR 2 直接受益）。
- `customAttributes.contract.test.js` 锁定 §1.12/§1.13 部分语句——编辑 §1.12 时保留被锁原文，先读测试再改文档。
- lifecycle 三键剥离让未来再生成 diff 更小（非更大）；badge 字段是唯一新增 payload 键，且 milvus/S3 两条公开 lane 均不含它。
