## Interfaces and trust boundary

- `ReadResult<T>`: `{kind:'found',value:T}` | `{kind:'absent',evidence:BlobRef[]}` | `{kind:'unknown',reasons:string[]}`. A pure `classifyRemoteRead(observation)` consumes a strict normalized observation: response status (`success`, `not-found`, `forbidden`, `rate-limited`, `server-error`, `timeout`, `graphql-error`), repositoryReadable, endpointScopeVerified, paginationComplete, exactInventoryMatches, value or null, and retained evidence. Only complete authenticated success produces found; absent requires not-found, readable repository, correct scope, complete bounded inventory with zero exact matches and evidence. Everything uncertain holds unknown; multiple matches are ambiguous. No HTTP requests or raw error strings enter this classifier.
- `RemotePolicy`: github.com host, numeric repository ID and full name, base ref `master`, allowed head prefixes, actor ID, check App ID, workflow ID/path/definition SHA-256, allowed event (`workflow_dispatch`), and artifact/check names. Policy is independently trusted caller input, never read from candidate content.
- `ExactValidationExpected`: repository/PR identity, branch, current base OID, seal/head S, master M, dev D, tools M, unitKey, planSha256, requestId, runId and runAttempt. It supplies exact intent rather than selecting a convenient successful run.
- `RemoteFacts`: outer wrapper retains ObservedPr v1 and adds repository identity/full name/host, base/head repository identity, base/head ref names, reobserved master/dev, and read-result collections for runs, checks, artifacts and seal facts, plus retained evidence. All reads must be found and complete. Bounded arrays preserve duplicate claims so uniqueness can be checked rather than silently deduplicated.
- Run fact: numeric ID/attempt, repository/head-repository IDs, actor ID, event, workflow ID/path/definition digest, tooling head OID, status/conclusion, check-suite ID, evidence. Check fact: ID, name, App ID, run/suite IDs, run attempt, target head S, status/conclusion, evidence. Artifact fact: ID/name, run ID/attempt, expired flag, API SHA-256 digest, actual-byte SHA-256 digest, byte length and retained BlobRef. Byte digest is independently computed by a future adapter; slice 1 compares it and its BlobRef binding, never reads bytes or authenticates API provenance.
- `RemoteSealV1`: kind `shared-update-seal`, schemaVersion 1, repositoryId, transactionId, unitKey, planSha256, proofSha256, master M, dev D, preparedBase P, candidate K, candidateTree, previousSeal (explicit null allowed), preservedHumanHeads, runId/runAttempt. Separate from BotRevision; seal observation binds seal OID S, single parent K, same tree, valid signature and verified signing actor. No new message codec or writer.
- `ExactValidationReceiptV1`: kind `shared-update-exact-validation`, schemaVersion 1, repositoryId, prNumber, head S, master M, dev D, tools M, unitKey, planSha256, seal S, requestId, runId/runAttempt, workflowPath, workflowDefinitionSha256, outputDigest, conclusion. Receipt is parsed from strict canonical JSON with duplicate-key rejection; supplied artifact fact binds the receipt's canonical byte digest to API/observed/BlobRef digests and outputDigest to an independently retained output BlobRef.
- `acceptExactValidation(expected, apiFacts, receipt, policy): Decision`, where Decision is strict `{status:'accepted',evidence:BlobRef[]}` | `{status:'hold',reasons:string[]}`. Validate all inputs; malformed input returns stable sanitized reason codes, never raw input/Zod messages. No network, Git, filesystem, environment, clock, captureTrustedToolset, or writer capability. Expiration and completeness are explicit observations, not inferred from local time.

This function establishes consistency under the caller's trust assumptions only. JSON cannot create authenticated observations or a writer capability. A future trusted adapter must authenticate API identities, immutable artifact bytes, workflow definitions, and signature evidence. Dispatch run head is M; the receipt/check separately bind S. Do not require dispatch head S or equate signed commit identity with workflow execution identity.

## Bounds and fail-closed behavior

Use `.strictObject` at every object boundary, required fields and explicit nulls. Bound IDs to positive safe integers; OIDs/digests to existing formats; text to valid Unicode without controls. Limits: 256-character identities/refs/unitKey, 512-character repository/workflow/evidence paths, 128-character reason codes, 64 reasons/evidence refs, 16 preserved heads, 32 runs/checks/artifacts, 64 KiB receipt/seal canonical payload, 1 MiB retained validation output. Enforce bounds before canonical serialization; no secret-bearing diagnostics. No changes to existing global schema limits.

Require exact policy/intent matches, open draft PR, base master and allowed head prefix, current PR S/base OID and master M/dev D unchanged, tools M, seal parent/tree/signature/actor binding, run actor/event/workflow/attempt/tooling-head match, completed successful run and check, correct suite/run/App/check target, one matching run and artifact, nonexpired artifact, receipt/run/request identity and all digest bindings. Reject zero or multiple matching claims, conflicting duplicates, old attempts, pending/failure/cancelled/skipped results, missing/malformed receipt and any unknown read. Same check name never substitutes for correct App ID. No mutation of input or evidence arrays.
