## Interfaces and trust boundary

- `ReadResult<T>`: `{kind:'found',value:T}` | `{kind:'absent',evidence:BlobRef[]}` | `{kind:'unknown',reasons:string[]}`. A pure `classifyRemoteRead(observation)` consumes a strict normalized observation: response status (`success`, `not-found`, `forbidden`, `rate-limited`, `server-error`, `timeout`, `graphql-error`), repositoryReadable, endpointScopeVerified, paginationComplete, exactInventoryMatches, value or null, and retained evidence. Only complete authenticated success produces found; absent requires not-found, readable repository, correct scope, complete bounded inventory with zero exact matches and evidence. Everything uncertain holds unknown; multiple matches are ambiguous. No HTTP requests or raw error strings enter this classifier.
- `RemotePolicy`: github.com host, numeric repository ID and full name, base ref `master`, allowed head prefixes, check App ID and artifact/check names; separate producer and validator policy identities each specify actor ID, workflow ID/path/definition SHA-256 and allowed event (`workflow_dispatch`). Policy is independently trusted caller input, never read from candidate content.
- `ExactValidationExpected`: repository/PR identity, branch, current base OID, seal/head S, master M, dev D, tools M, unitKey, planSha256, requestId, validatorRunId/validatorRunAttempt, plus explicit producerRunId/producerRunAttempt, producerRequestId and transactionId. It supplies exact intent rather than selecting a convenient successful run.
- `RemoteFacts`: outer wrapper retains ObservedPr v1 and adds repository identity/full name/host, base/head repository identity, base/head ref names, reobserved master/dev, and read-result collections for producer runs, validator runs, producer provenance receipts, checks, artifacts and seal facts, plus retained evidence. All reads must be found and complete. Bounded arrays preserve duplicate claims so uniqueness can be checked rather than silently deduplicated.
- Separate `ProducerRunFact` and `ValidatorRunFact`: numeric ID/attempt, repository/head-repository IDs, actor ID, event, workflow ID/path/definition digest, tooling head OID, status/conclusion and evidence; validator additionally has workflowSuiteId/workflowSuiteHead at tooling M, describing its Actions suite only. `ProducerProvenanceFact` binds the independently authenticated producer run/attempt, producerRequestId, transactionId, S/K, repository, M/D/P, unit/plan/proof identities and retained immutable producer receipt. Validate producer identity against producer policy and expected producer identity; validation success cannot replace missing producer provenance. Target check fact: check ID, name, App ID, target suite ID, target head S, status/conclusion and retained evidence. Separate `ValidationCheckAssociationFact`, authenticated through the exact immutable validation receipt provenance, binds validator run ID/attempt/requestId to target check ID/suite ID/App ID/head S. Require all association fields to match observed target check and expected validator intent. A caller-provided runId on a check is insufficient. The target suite at S is independent of the workflow Actions suite at M and must not be forced equal.
- `ArtifactFact`: ID/name, owner run ID/attempt, expired flag, archive API SHA-256 digest, downloaded archive actual-byte SHA-256 digest, archive byte length and retained archive BlobRef. Require equality only within this archive domain. An adapter-authenticated `ArtifactMemberFact` binds artifact ID, archive digest, exact confined member path, member actual-byte SHA-256 digest/length and retained member BlobRef. The trusted adapter verifies archive ownership, unique member selection and safe bounded extraction; the pure predicate checks these supplied associations and holds on missing/ambiguous/conflicting associations. Receipt JSON is an extracted member, never the archive itself. Output is a separate retained BlobRef bound to the receipt outputDigest; if archived, its member fact independently binds it to the archive.
- `RemoteSealV1`: kind `shared-update-seal`, schemaVersion 1, repositoryId, transactionId, unitKey, planSha256, proofSha256, master M, dev D, preparedBase P, candidate K, candidateTree, previousSeal (explicit null allowed), preservedHumanHeads, runId/runAttempt (the producer execution identity). Separate from BotRevision; seal observation binds seal OID S, single parent K, same tree, valid signature and verified signing actor, independently authenticated producer provenance and expected producerRunId/producerRunAttempt. Producer and validator IDs may differ and normally do; neither identity is inferred from the other. No new message codec or writer.
- `ExactValidationReceiptV1`: kind `shared-update-exact-validation`, schemaVersion 1, repositoryId, prNumber, head S, master M, dev D, tools M, unitKey, planSha256, seal S, requestId, runId/runAttempt, workflowPath, workflowDefinitionSha256, targetCheckId, targetSuiteId, targetCheckAppId, targetCheckHead S, outputDigest, conclusion. Receipt is parsed from strict canonical JSON with duplicate-key rejection; its canonical bytes must match the extracted receipt member's actual-byte digest, length and retained member BlobRef. The authenticated member association binds that member to the artifact archive, whose API/downloaded/retained digests are checked separately. outputDigest binds an independently retained output BlobRef, never the archive or receipt digest. The receipt target-check fields must match the authenticated ValidationCheckAssociationFact and observed target check; swapped or stale associations hold. Receipt runId/runAttempt identify the validator and must match the expected validator identity, not the producer seal execution.
- `acceptExactValidation(expected, apiFacts, receipt, policy): Decision`, where Decision is strict `{status:'accepted',evidence:BlobRef[]}` | `{status:'hold',reasons:string[]}`. Validate all inputs; malformed input returns stable sanitized reason codes, never raw input/Zod messages. No network, Git, filesystem, environment, clock, captureTrustedToolset, or writer capability. Expiration and completeness are explicit observations, not inferred from local time.

This function establishes consistency under the caller's trust assumptions only. JSON cannot create authenticated observations or a writer capability. A future trusted adapter must authenticate API identities, immutable artifact bytes, workflow definitions, signature evidence and archive/member provenance. Producer and validator policies, expected identities, run facts and immutable receipts are checked independently. Dispatch run head is M; the receipt/check separately bind S. Do not require dispatch head S or equate signed commit identity with workflow execution identity.

## Bounds and fail-closed behavior

Use `.strictObject` at every object boundary, required fields and explicit nulls. Bound IDs to positive safe integers; OIDs/digests to existing formats; text to valid Unicode without controls. Limits: 256-character identities/refs/unitKey, 512-character repository/workflow/evidence paths, 128-character reason codes, 64 reasons/evidence refs, 16 preserved heads, 32 runs/checks/artifacts, 64 KiB receipt/seal canonical payload, 1 MiB retained validation output, 16 MiB archive, 64 bounded members per archive and 512-character confined member paths. Enforce bounds before canonical serialization; no secret-bearing diagnostics. No changes to existing global schema limits.

Require exact policy/intent matches, open draft PR, base master and allowed head prefix, current PR S/base OID and master M/dev D unchanged, tools M, seal parent/tree/signature/actor binding, run actor/event/workflow/attempt/tooling-head match, completed successful run and check, correct separate workflow-suite head M and target-suite/check head S, exact authenticated validator/run/attempt/request-to-target-check association, one matching producer run/provenance and one matching validator run/artifact, nonexpired artifact, receipt/run/request identity and all digest bindings. Reject zero or multiple matching claims, conflicting duplicates, old attempts, pending/failure/cancelled/skipped results, missing/malformed receipt and any unknown read. Same check name never substitutes for correct App ID. No mutation of input or evidence arrays.
