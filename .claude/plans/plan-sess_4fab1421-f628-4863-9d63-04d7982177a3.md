# 修复 shared-docs 构建缺失的 accidental math span 修复（打通翻译循环）

## Context

11-12 RCA 定案：`json-field-overview.md`（guides+byoc 双胞胎，shared-docs 页）源文件含裸 `$meta</code>: <code>$meta`，被 remark-math 配成伪 math span → ja 翻译 source preflight 确定性 fail-closed → 每轮定时 translate 重选同一文件无限重试（零翻译成本）。

根因：Fetch writer 侧修复 `repairAccidentalMathSpans`（larkDocWriter.js:1488）只覆盖 Feishu 路径；**shared-docs 构建管线（`packages/docs-tooling/src/shared-docs/commands/build.ts`）完全没有此修复**。修复函数本身对该文件实测有效（检出 1 span、修复成功、0 残留）。

契约侦察结论（已验证，无破坏）：
- 发布时校验（finalize/promote/checkpoint validate）从不重执行构建 → 存量 receipt/proof 不受影响。
- Fetch 每轮重建所有 shared 页并重写 receipt+proof（新 output hash + 新 `tools.zdoc`）；同 run 的 `regenerateReceipt` 重放跑同一份新 build.ts → 字节一致。
- build.ts 在 `guides-assembly-identity.js` 的 FINGERPRINT_FILES 里 → 改动会触发 `regenerate` 全量重渲。预期行为。
- 修复模块保证输出要么干净要么原样返回（accidentalMathSpans.js:172-205）→ 重放确定性保持。

## 改动（feature 分支，单个 master PR）

### 1. `packages/docs-tooling/src/shared-docs/commands/build.ts`
- 用 `createRequire(import.meta.url)` 加载 `../../markdown/accidentalMathSpans.js` 的 `repairAccidentalMathSpans`（md2md.ts:1-6 先例；**必须绕开 jiti 对 import() 的 require 降级**——模块内部动态 import ESM-only 的 @mdx-js/mdx，理由同 adapters/mdx.ts:8-16 的 importEsm 注释）。
- `runBuild` 页面循环成功后、`buildImageManifest`（:203）前：对每个 `page.mdx` 跑修复，repaired 则替换字符串；经现有 `write()` 回调输出归属警告（措辞对齐 larkDocWriter.js:1378-1387：repaired N spans / remaining spans）。
- remaining 非空**不使构建失败**（对齐 larkDocWriter.js:1370-1377 的显式策略"never fail the run"）；翻译源预检仍是下游 fail-closed 兜底。

### 2. `scripts/docs-workflow/guides-shared-regeneration.js`
- `assertToolIdentity` inventory roots（:46-47）加 `packages/docs-tooling/src/markdown`——构建输出现在依赖它，重放凭据对新依赖保持密闭。已确认无测试 pin 该 roots 列表。
