# milvus.io REST 参考页 Zilliz 专有内容泄漏 — 修复计划

## Context

web-content#1250（已合并）把 milvus.io 的 RESTful v2 参考切换为从 zdoc 片段全集渲染：latest 线 (v3.0.x) 渲染完整片段集，2.6.x 走 lifecycle 投影。片段中**未经 target 作用域保护**的 Zilliz 专有内容因此原样出现在 milvus.io 上。已确认三处：

1. **"Milvus version compatibility" note**（用户报告）— `04-vector-operations-v2.json` 行 2067/3124/4325，挂在 query/search/hybrid_search 三个操作的 `x-admonition` 上。第二句 "On Zilliz Cloud, serverless clusters…" 是 Zilliz house style（zdoc #1005 引入）；且 2.6.x 投影页也在显示（admonition 无生命周期戳），在该页引用了未文档化的参数，更加荒谬。
2. **tiered storage / usage tracking 描述**（用户报告）— `scanned_remote_bytes`/`scanned_total_bytes`/`cache_hit_ratio` 三个响应字段的描述，出现在 upsert/query/search/hybrid_search/get 的响应 schema 中。注意：milvus OSS 内核确实有 ScannedRemoteBytes/ScannedTotalBytes（segcore/querynodev2/streamrpc），即用户判断"内核开放给云的功能"很可能成立——字段可能共享，错的只是 "with usage tracking enabled" 这个 Zilliz 计费口径短语。
3. **新发现的第三处** — `07-index-operations-v2.json`：Index Drop Properties 的 note "Collections for **on-demand compute** do not support this operation."（on-demand compute 是 Zilliz Cloud 计费概念，milvus.io 无此概念；相邻 Drop 的 "External collections" note 需一并分类）。

根因类别：片段是单一真源、双端消费（zdoc target=zilliz latest-only；milvus.io target=milvus 按版本），系统有现成的 target 作用域机制但这两类内容没使用——节点级 `x-include-target`（integratedSpecBuilder `filterSelection` 已支持任意节点粒度，含 property+required 重同步、admonition 数组成员逐条）和句子级 `<include/exclude target="...">` 行内 span（zdoc 运行时与 web-content 运行时均已实现，milvus.io 线上已验证正常解析）。
