## 1. Read boundary and proof sources

- [ ] Add `createRemoteReads({policy, transport?, evidence})`. Methods: `readRepository()`, `readRef(ref)`, `readPull(number)`, `scanPulls()`, `readCommit(oid)`, `readRun({id,attempt,role})`, `readChecks(oid)`, `readArtifact({runId,attempt,name})`; each returns `RemoteReadResult<T>` with strict bounded fact schemas in `remote.ts`. Retain raw response bodies and derived immutable observations in EvidenceStore, returning BlobRefs. Private WeakSet/WeakMap membership identifies authentic adapter results; parsed JSON cannot create that membership.
- [ ] Inject transport only at the raw boundary: `(request: ReadonlyRequest) => Promise<{status,headers,body:Uint8Array}>`. It supplies bytes and HTTP status, **asserts network authenticity**, and is trusted caller code, never request JSON. The adapter itself verifies all identities, digests, schema, pagination and bindings. Default transport uses fixed github.com/API hosts and fixed GET endpoints plus one constant read-only GraphQL commit-signature query; no arbitrary public URL/query interface, POST mutation, redirect credential forwarding or candidate subprocess. Artifact download uses the fixed artifact-ID endpoint; any redirect follows only HTTPS GitHub artifact storage destinations without credentials and with a bounded redirect count. Transport exceptions become fixed reason codes, never stderr/token text.
- [ ] REST facts bind numeric repository ID/full name, PR base/head repositories, base=master, branch namespace, writer actor, exact SHA; run facts bind exact attempt endpoint, event, workflow ID/path, actor, head repository/tooling SHA, and workflow bytes fetched at that SHA and hashed against trusted policy. Run initiator and writer actor are separate. Checks bind numeric App/check/suite/head and completed success, preserving workflow suite at M separately from target suite at S.
- [ ] Signature read binds GraphQL repository/object OID, API commit author/committer numeric identity, signature validity/state, signed payload/signature and raw commit header consistency. Do not equate signature.signer (GitHub signing identity/email association) with API writer identity; see approval decisions below. No author string or copied trailer authenticates a commit.
- [ ] Collections: page size 100, maximum 20 pages/2,000 entries, exact stable identity uniqueness, total-count/Link continuity where available, terminal page required, before/after repository/ref/PR/run reads unchanged. Duplicates, count mismatch, missing pages, truncation or cap exhaustion => unknown. HTTP 404 => absent only for refs/PRs after readable matching repository plus complete exact inventory exclusion; all other unsupported absence classifications => unknown. 403/429/5xx/timeout/GraphQL errors => unknown. Scan all open PRs on base master before grouping by authenticated subjects; same namespace with unknown origin blocks overlapping units conservatively (unknown subjects block every scanned unit), never silently discard it.
- [ ] JSON body 1 MiB, receipt 64 KiB, expanded member 1 MiB, ZIP 16 MiB, members 64, cumulative expanded ZIP 16 MiB; fixed 30-second request and 120-second inspection deadline, max 512 API calls. Reuse existing smaller REMOTE_LIMITS for normalized fact collections/evidence; exceeding any bound holds rather than truncates. Safe ZIP parsing rejects duplicate/case aliases, traversal, links, encryption, unsupported compression and size/CRC mismatch without filesystem extraction. Require unique named artifact, nonexpired, repository/run/head ownership, API SHA-256=archive bytes digest, member digest separately. Re-read artifact metadata after download. Receipt attempt is not API-authenticated merely because it appears in JSON.

## 2. Complete raw object graph and remote history

- [ ] Add `inspectRemoteHistory({head,donorHeads,master,policy}, reads, objects)`. `objects.read(oid,type)` supplies only raw commit/tree/blob bytes, with fixed per-object and cumulative limits; **it does not assert ancestry, metadata, signature or authority**. Hash `type + space + byteLength + NUL + bytes` independently to the requested canonical lowercase SHA-1 OID. No rev-list, shallow boundary, replace ref, graft, lazy fetch, checkout or candidate code participates. Missing object holds. This raw dependency allows real temporary Git object fixtures on Linux without trusted capture.
- [ ] Walk every parent to root for current master, H and donors with one memoized graph and shared budget: 100,000 commit headers, 256 non-master commits, 32 merges, 4 MiB discovery messages, 8 donors, max two unique parents; strict raw header parser handles continuation headers without allowing hidden mandatory fields. Decode trailers only outside complete master ancestry. Raw trees recursively verify canonical ordering, unique UTF-8 names, modes/OIDs, 32 MiB tree bytes/100,000 expanded leaves; compare entire mode/path/OID maps, not a claimed diff. Blob reads are capped at 1 MiB; raw total object bytes 64 MiB. Timeout/cycle/malformed/oversized/incomplete graph holds; no early first-trailer acceptance.
- [ ] Parse distinct canonical `Shared-Update-Seal` message and original `parseRevisionMessage` on K. Require S parents=[K], tree(S)=tree(K), K parents=[P]. Read producer run/artifact provenance for each historical S, binding S/K/tree/P/previousSeal, M/D, transaction/unit/plan/proof, preserved heads, run/attempt/request. Historical tools=M is authenticated against that historical trusted workflow definition, never current M or mere ancestry. Producer bundle schema adds bounded canonical plan, CandidateSnapshotProof and report members with SHA-256/size bindings; it is explicitly an offline contract until a trusted producer exists.
- [ ] Verify raw K revision bindings against authenticated plan/proof: P/tree, K/tree, reports and plan digests, subjects/members, next edits and preserved heads. Use `assertNextOnlyDiff` on independently reconstructed **complete** P→K tree differences, exact modes and before/after bytes. Compare proof.patch to independently encoded raw Git diff. Reconstruct deterministic K bytes using B2 commit convention. Verify previousBotCommit→previous K, previousSeal→authenticated S and ancestry/chain completeness; first revision requires a proved new baseline or explicitly authenticated preserved human origin, otherwise hold. No local journal callback or normalized `verified:true` shortcut.
- [ ] Human successors above S may include ordinary merges: traverse all parents; retain every requested H/donor as preserved head, require authenticated same-unit seal ancestry, compare every nonsealed edge outside master ancestry against candidate execution inputs. Conservatively permit only ordinary regular-file data changes under documented shared-docs content roots; lock/trailer changes, executable modes, links/submodules, config/tooling/workflow/package changes or unclassifiable roots hold. Verify ordinary merge parent ancestry and complete trees; do not discard second parents. Select latest seal only when same-unit authenticated revisions are comparable; incomparable/erased previous chains hold. Return deeply immutable graph/evidence/counts plus opaque WeakMap-backed history capability; serialization loses authority.

## Approval decisions / safe stops

1. Signature signer is not necessarily writer (GitHub platform signing key versus bot API actor). Proposed accepted predicate requires GitHub valid signature bound to exact raw S plus API committer user numeric writerActorId and authenticated producer provenance; retain signing identity separately, never populate it from a nickname. Clarify `remote.ts` seal facts by separating signature verification/signing identity from numeric API writer attribution; existing `signingActorId` must not silently change meaning or be filled from committer attribution. If the intended policy requires signature.signer numeric ID=writerActorId, hold where GitHub cannot expose that match; no guessed platform identity.
2. Artifact REST schema exposes run ID but no attempt. Attempt intervals are corroboration only. Require exact-attempt API facts plus fixed producer workflow bytes at historical M whose reviewed contract emits the canonical bundle only from that attempt, with repository/run/attempt/S/K and artifact member digests bound in those trusted bytes and checked against immutable API ownership/digest. Re-read metadata before/after; ambiguous/reused or independently unprovable attempt ownership holds (never assign current run_attempt or infer ownership from timestamps). Producer/validator workflow is absent, so no production capability can currently pass.
3. Producer archive layout and exact seal message framing are not installed protocols. Proposed local contract: strict canonical receipt/bundle with deterministic fixed member names, explicit original B2 schemas and digest references, exact single versioned seal trailer. No fixture is claimed as captured real producer evidence. Root should approve these bounded contracts and the conservative human-data allowlist before implementation; no writing/runner integration is needed to test them.
