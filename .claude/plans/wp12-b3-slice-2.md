# WP12-B3 slice 2 implementation plan

Goal: read bounded GitHub facts and independently authenticate remote revision history without executing candidate code or issuing mutations. Product baseline: `87f103f926d27943861278181308ebbb7cb73fe0`. [Fixed design task card](https://github.com/liyun95/milvus-zilliz-docs-design/blob/4cc9e9436e6e9670443276196734979653065300/docs/implementation/tasks/WP12-zdoc-upstream-updates.md).

No runner, writer, CLI, workflow, local inspector or frozen B2 envelope changes. This temporary plan is removed after code review and before final gates.

## 1. Read boundary and proof sources

- [ ] Add `createRemoteReads({policy, transport?, evidence})`. Methods: `readRepository()`, `readRef(ref)`, `readPull(number)`, `scanPulls()`, `readCommit(oid)`, `readRun({id,attempt,role})`, `readChecks(oid)`, `readArtifact({runId,attempt,name})`; each returns `RemoteReadResult<T>` with strict bounded fact schemas in `remote.ts`. Parse exact bounded response bytes in memory; retain canonical allowlisted field projections and original-body SHA-256, not raw headers/URL-bearing JSON. Retain exact signature payload, object and bundle bytes as BlobRefs. Evidence projections are observations, not replayable network authentication. Private WeakSet/WeakMap membership identifies authentic adapter results; parsed JSON cannot create that membership.
- [ ] Zero new dependencies: default transport uses `node:https.request`, streaming byte counters before concatenation, AbortSignal and one shared deadline/call budget; credential lookup is `GH_TOKEN ?? GITHUB_TOKEN` from trusted process environment only (missing => unknown), never candidate config, subprocess, token in URL or evidence. The trusted injectable raw transport returns `{status,headers,body:Uint8Array}` and asserts network origin only; all fact validation stays in the production parser. Fixed REST prefix `/repos/{policy.repositoryFullName}` permits only repository GET; `git/ref/heads/{encodedRef}`, `git/matching-refs/heads/`, `pulls[/number]`, `commits/{oid}`, `commits/{oid}/check-runs`, `actions/runs/{id}[/attempts/{attempt}]`, `actions/workflows/{id}`, `contents/{approvedWorkflowPath}?ref={tools}`, `actions/runs/{id}/artifacts`, `actions/artifacts/{id}[/zip]`. Query keys are constructed internally (`per_page/page/state/base/filter/ref`), never accepted as free strings. `POST api.github.com/graphql` carries one constant query (repository numeric identity, commit OID, author/committer databaseId, signature payload/signature/state/isValid/wasSignedByGitHub/signer); no mutation or caller query. HTTPS API host only, no userinfo/port. Artifact endpoint may redirect once to HTTPS port 443 hosts ending `.blob.core.windows.net` or `.actions.githubusercontent.com`; no further redirects, no Authorization/Cookie forwarded. Unrecognized delivery host holds pending qualification. Retain only status, content-type, numeric pagination/count/rate fields and validated next-page number, dropping Location, signed query strings, cookies and auth. Diagnostics are fixed codes. A local HTTP fixture supplies the socket request function behind the same private streaming decoder/redirect parser; production host policy remains unchanged. No automatic retries.
- [ ] REST facts bind numeric repository ID/full name, PR base/head repositories, base=master, branch namespace, writer actor, exact SHA; run facts bind exact attempt endpoint, event, workflow ID/path, actor, head repository/tooling SHA, and workflow bytes fetched at that SHA and hashed against trusted policy. Run initiator and writer actor are separate. Checks bind numeric App/check/suite/head and completed success, preserving workflow suite at M separately from target suite at S.
- [ ] Clarify seal fact schema in `remote.ts`: replace ambiguous `signingActorId` with separate signature state/validity/GitHub-signed flag/signer observation and `writerAttribution:{role:'committer',actorId}`. Require API committer user databaseId=`policy.writerActorId`, never author-or-committer fallback. Retain API author and signer independently; nullable unsupported attribution holds. Require GraphQL `isValid=true`, `state=VALID`, `wasSignedByGitHub=true`, REST verification valid and same payload/signature. Reconstruct exact raw S by inserting the sole multiline `gpgsig` header (one space prefix for continuation lines) into signed payload at its raw header position, remove it again and require exact payload bytes; compare signature bytes and full raw S bytes/OID. Reject duplicate signature headers, alternate signing formats or any reconstruction ambiguity. API attribution does not attest workflow origin; producer authority below remains mandatory. Live bot role/signature qualification is deferred; fixture IDs grant no production authority.
- [ ] Collections: page size 100, maximum 20 pages/2,000 entries, exact stable identity uniqueness, total-count/Link continuity where available, terminal page required, before/after repository/ref/PR/run reads unchanged. Duplicates, count mismatch, missing pages, truncation or cap exhaustion => unknown. HTTP 404 => absent only for refs/PRs after readable matching repository plus complete exact inventory exclusion; all other unsupported absence classifications => unknown. 403/429/5xx/timeout/GraphQL errors => unknown. Scan all open PRs on base master before grouping by authenticated subjects; same namespace with unknown origin blocks overlapping units conservatively (unknown subjects block every scanned unit), never silently discard it.
- [ ] JSON body 1 MiB, receipt 64 KiB, expanded member 1 MiB, ZIP 16 MiB, members 64, cumulative expanded ZIP 16 MiB; fixed 30-second request and 120-second inspection deadline, max 512 API calls. Reuse existing smaller REMOTE_LIMITS for normalized fact collections/evidence; exceeding any bound holds rather than truncates. Implement an in-memory bounded ZIP central/local-directory parser in remote-github.ts using node:zlib inflateRawSync with maxOutputLength and a small CRC32 routine; stored/deflate only. Match local and central names/flags/sizes/CRC/offsets, support bounded single-disk non-ZIP64 bit-3 data descriptors: central sizes locate the exact compressed range, then parse the signed 16-byte or unambiguously unsigned 12-byte descriptor; require descriptor CRC/compressed/uncompressed sizes equal central values and actual inflated size/CRC, accepting local zero placeholders only with bit 3. Reject missing/conflicting/truncated/ambiguous descriptors, overlapping header/data/descriptor/central ranges, ZIP64/multidisk, duplicate/case aliases, traversal, links, encryption, trailing ambiguity and unsupported compression. Unsupported genuine archives hold, never fall back to shell extraction. Require unique named artifact, nonexpired, repository/run/head ownership, API SHA-256=archive bytes digest, member digest separately. Re-read artifact metadata after download. Receipt attempt is not API-authenticated merely because it appears in JSON.

## 2. Complete raw object graph and remote history

- [ ] Add `inspectRemoteHistory({head,donorHeads,master,policy}, reads, objects)`. `objects.read(oid,type)` supplies only raw commit/tree/blob bytes, with fixed per-object and cumulative limits; **it does not assert ancestry, metadata, signature or authority**. Hash `type + space + byteLength + NUL + bytes` independently to the requested canonical lowercase SHA-1 OID. No rev-list, shallow boundary, replace ref, graft, lazy fetch, checkout or candidate code participates. Missing object holds. Default production object acquisition is NOT delivered: objects is a required trusted byte-reader dependency, with no auto-fetch, ambient git or credential bridge. Missing dependency yields hold. Tests supply raw cat-file bytes from temporary bare Git objects on Linux; hash/traversal checks remain production code. Future production acquisition is a separate bridge, not an assertion hidden in this slice.
- [ ] Walk every parent to root for current master, H and donors with one memoized graph and shared budget: 100,000 commit headers, 256 non-master commits, 32 merges, 4 MiB discovery messages, 8 donors, max two unique parents; strict raw header parser handles continuation headers without allowing hidden mandatory fields. Decode trailers only outside complete master ancestry. Raw trees recursively verify canonical ordering, unique UTF-8 names, modes/OIDs, 32 MiB tree bytes/100,000 expanded leaves; compare entire mode/path/OID maps, not a claimed diff. Blob reads are capped at 1 MiB; raw total object bytes 64 MiB. Timeout/cycle/malformed/oversized/incomplete graph holds; no early first-trailer acceptance.
- [ ] Parse distinct canonical `Shared-Update-Seal` message and original `parseRevisionMessage` on K. Require S parents=[K], tree(S)=tree(K), K parents=[P]. Read producer run/artifact provenance for each historical S, binding S/K/tree/P/previousSeal, M/D, transaction/unit/plan/proof, preserved heads, run/attempt/request. Historical tools=M is authenticated against that historical trusted workflow definition, never current M or mere ancestry. Use the precise offline bundle contract below; absent approved producer authority holds.
- [ ] Verify raw K revision bindings against authenticated plan/proof: P/tree, K/tree, reports and plan digests, subjects/members, next edits and preserved heads. Use `assertNextOnlyDiff` on independently reconstructed **complete** P→K tree differences, exact modes and before/after bytes. Reconstruct proof.patch exactly as UTF-8 `:oldmode newmode oldoid newoid M` + NUL + path + NUL per modified path, sorted by Git raw tree/path ordering, with no textual patch/header/newline (matching diff-tree --raw -r -z --no-abbrev --no-color --no-renames --no-ext-diff --no-commit-id). Rebuild K raw bytes as `tree T\nparent P\nauthor Shared update local <shared-update-local@localhost> t +0000\ncommitter Shared update local <shared-update-local@localhost> t +0000\n\n` plus exact encodeRevisionMessage output, t=P committer timestamp+1; compare raw bytes and OID, not merely tree. Verify previousBotCommit→previous K, previousSeal→authenticated S and ancestry/chain completeness; first revision requires a proved new baseline or explicitly authenticated preserved human origin, otherwise hold. No local journal callback or normalized `verified:true` shortcut.
- [ ] Human successors above S and prepared merges preserve all H/donor roots and ordinary second parents. Allowed candidate data paths are exactly descendants of `shared-docs/guides/`, `content/en/guides/`, `content/en/byoc/`, excluding `protectedToolsetPath(path)`; permit blob modes 100644/100755 as B2 does, including YAML/JSON configuration inside those roots. Human lock edits may be data (B2 next-only applies only P→K); spoofed revision/seal trailers still hold. Links/submodules/protected executable extensions or outside-root edits hold. Configuration outside these roots is explicitly unsupported in this slice, not a claim that the future bridge may discard it.
- [ ] For each ordinary merge find its unique maximal common ancestor in the complete graph. Accept a bounded disjoint merge only: compare base→left and base→right mode/path/OID maps, reject overlapping changed paths, and require merged tree exactly the union of both changes (including deletions). Attributes or ambiguous bases hold. A parent on complete current-master ancestry is trusted master data: its protected changes may enter only by this exact union, not as arbitrary merge-result edits. Candidate-side protected changes hold even if later reverted; compare all non-master/nonsealed edges, not only final tree. Both candidate-data parents may merge disjoint permitted changes; conflicts/resolutions and unsupported merges hold explicitly. Historical P’s merge/preservation evidence must agree with raw parents, deterministic B2 merge framing, exact trees/diffs and preserved-head ancestry; no git merge code is executed. Test legitimate human data/config merge plus exact trusted-master tooling merge, injected third-result tooling changes, overlapping edits, attributes and hidden second-parent execution changes.
- [ ] Select latest seal only when same-unit authenticated revisions are comparable; incomparable/erased previous chains hold. Return immutable graph/evidence/counts plus opaque WeakMap-backed capability; serialization loses authority.

## Explicit authority and offline bundle contract

- Trusted caller supplies a finite approved producer-definition registry keyed by exact historical tools M and workflow ID/path/definition SHA-256, actor ID and protocol version; entries describe reviewed token isolation (candidate code never sees upload token), exclusive bundle output and run/attempt parameter derivation from GitHub context. It is separate from downloaded receipt data and current request policy, cannot be extended by receipt-provided digests, and has no installed/trusted Boolean. Production default registry is empty. Re-read workflow bytes at M, exact run attempt facts and run repository/head/event/actor against an approved entry. Missing definition or any unprovable isolation/attempt ownership => hold. Synthetic caller registry exercises predicates only.
- Artifact API lacks attempt: unique nonexpired API artifact ownership/digest authenticates archive identity at run scope; approved producer code plus exact-attempt API facts and receipt repository/run/attempt/S/K/request binds the attempt. Timestamp intervals only corroborate. Re-read exact run/attempt and artifact identity/digest/expiry after download; original archive digest fixes receipt immutability, strict unique member bytes/digest fix the receipt; a metadata race or reused/ambiguous attempt holds. No receipt JSON by itself proves either workflow or attempt.
- Exact offline archive members: `provenance.json` (new strict canonical producer receipt binding seal fields, request, tools, approved definition digest and ordered member BlobRefs); `plan.json` (UpdateUnitPlanSchema); `proof.json` (CandidateSnapshotProofSchema); `patch.raw` (exact NUL bytes); `reports/<raw-sha256>.json` for every plan.reports entry (UpdateReportEnvelopeSchema with validateUnitReports); `locks/<raw-sha256>.yaml` for every nextEdits.afterBlob; and `evidence/<raw-sha256>` for existing prepared mergeEvidence/preservationEvidence plus their referenced diff bytes. Require exact expected member inventory, no omissions/extras or multiply named digest aliases. Read every listed member, schema-parse canonical JSON, validate referenced digest/byte size independent of archive SHA. Read raw before/after lock blobs through objects as well and compare after member bytes. Report nested external authority/detail/configuration evidence is producer-attested by pinned receipt, not freshly replayed; report canonical bytes/pins/subjects/member-set binding are independently checked.
- Digest domains: plan=`digest('plan',plan)`; member set uses existing envelope/domain functions; proof=`SHA256(canonicalBytes(proof))`, archive/member/patch/report bytes use raw SHA-256; transaction/seal framing uses existing remote schema fields with no new invented digest domain. Seal message is exactly `Seal shared update\n\nShared-Update-Seal: v1.<base64url(canonicalBytes(RemoteSealV1))>\n`, canonical round trip, unique trailer only.
- Do NOT include B2 executableClosure in the 1 MiB-member/16 MiB-expanded bundle: proof.executableClosure and trustedToolsetSha256 are historical producer-attested digest/size references, not freshly checked closure bytes or B2 execution. Independently check plan/proof/patch/lock/report/prepared-evidence bytes as above. Reject any contract requesting fresh historical closure reconstruction here; missing producer authority holds rather than treating closure as locally verified. Large required checked members hold at bounds. Default raw object acquisition and actual producer installation remain undelivered bridge work, explicitly reported as production evidence gaps.

No design contradiction found: offline slice 2 can prove the bounded parser/authentication contract without granting production capabilities. The supported disjoint merge subset and archive subset hold on richer valid inputs; they do not claim complete future bridge/platform coverage. Root approval is required before implementation.
