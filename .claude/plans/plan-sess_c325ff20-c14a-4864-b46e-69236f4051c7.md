# 链接本地化改写：docs.zilliz.com(.cn) → 相对链接 + milvus.io 按语言分流

## 背景（已核实）

dev 上中文内容里：14 个 REST 生成页的 specs JSON 带英文站绝对链接（zh 翻译文案里也有）；中文 guides/byoc 散文里 54 个文件有 `docs.zilliz.com.cn` 自站绝对链接；三个语言共 612 处 `milvus.io` 链接全部指向英文页。REST specs 的语种选择发生在**渲染时**（RestSpecs 组件按 `lang` prop 读 `x-i18n[lang].description ?? description`，markdown-it 渲染，今天零链接后处理）；散文链接走 Docusaurus remark 管线（今天也无链接处理）。

**方案：渲染期（REST specs）+ 构建期（remark 插件）改写，共享一个纯函数 helper。不改 OpenAPI fragments、不改任何已提交内容。** 理由：生成期不知道目标语言（一个 JSON 同时含三语字段）；内容不动则翻译管线 protected-span 字节校验（`scripts/translation/protectedContent.js`）完全不受影响，也无需 REST 重生成或 Feishu 重抓取；下次构建镜像即全量生效。

## 改写规则（单一来源）

对链接 href：
1. `https://docs.zilliz.com` / `https://docs.zilliz.com.cn` 开头（含 http 变体）→ 去掉 host 留路径+query+anchor；`ja-JP` 语境加 `/ja-JP` 前缀，en/zh-CN 直接相对路径（与 `larkDocWriter.js:3123` 既有先例、`docsRoute.ts` 的 withLocalePrefix 一致）。
2. `https://milvus.io` 开头：en 不变；zh-CN/ja-JP 时——路径以 `/docs/` 开头 → 插到 `/docs/{zh|ja}` 后；以 `/blog/` 开头 → 前插 `/{zh|ja}`；其余（`/api-reference/`、`/tools/`、裸 host）不变。幂等守卫：已带 `zh/ja/ko/zh-hant` 语言段的直接跳过（内容里已存在 `milvus.io/docs/zh/minhash-lsh.md`）。
3. 其它任何 URL 原样返回。

milvus.io 结构已逐一实测：真翻译在 `milvus.io/docs/zh/...`（v2.6.x）、`/docs/ja/...`（v2.5.x）、`/zh/blog/...`、`/ja/blog/...`；`/zh/api-reference/...`、`/zh/docs/...` 是软回退英文（canonical 指回英文 URL），故 api-reference 保持英文规范链。

## 改动清单

### 1. 共享 helper（新）
- `packages/docs-ui/src/shared/links/rewriteDocLinks.ts`：`rewriteDocHref(href, locale)`（上表规则）、`rewriteHtmlHrefAttributes(html, locale)`（regex 改写 `href="..."`，供 RestSpecs 用）、locale 归一（`en-US`→`en`）。

### 2. RestSpecs 渲染期（REST specs JSON 里的链接，三语一次覆盖）
- `packages/docs-ui/src/shared/components/RestSpecs/utils.js`：`textFilter(text, targets, lang)` 增加第三参，递归调用透传；最终 `sanitize` 后套 `rewriteHtmlHrefAttributes`。markdown 链接和内联 HTML `<a href>` 经 markdown-it 后统一是 `<a href>`，一处覆盖两种形态；include/exclude target 过滤在改写前完成，`<include target="milvus">` 内链接不会被错误处理。
- `index.js` 约 8 处 `textFilter(...)` 调用点补传 `lang`（各组件作用域内已有）。

### 3. remark 插件（guides/byoc/onpremise/SDK reference 散文链接）

## 已知边界与取舍（明确接受）
- `integrate-with-aws-s3`：zh 站无此页（en/ja 有）。改写后 zh REST 页（export-backup-files-v2）该链接从"跳英文页可用"变为"站内 404"。正解是补 zh 内容（另行任务），本次接受并报告。
- `reranker` / `faq-pipelines` / `building-a-rag-app-with-pipelines`：三语全站都不存在，本就是死链（v1 pipeline fragments 里的陈旧 URL）。改写只是把死链留在本语言内；修 fragment 属后续内容任务。
- 散文中 JSX `<a href>` 与裸 URL 文本不在本次范围（现有库存全是 markdown 链接形态）；`RestSpecs/i18n.js` 内置提示语已是各语种正确的相对链接，不涉及。
- llms.txt 等派生产物若单独读源内容，不在改写范围。

## 明确不做
不动 OpenAPI fragments、不重新生成 REST MDX、不动 dev 已提交内容、不动翻译管线与发布契约、不手改任何生成产物——所有改动在 master 工具/前端代码侧，按正常 master PR → sync 流程发布。
