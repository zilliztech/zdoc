# TRIE

`TRIE` は、文字列をプレフィックスツリーに格納し、正確な検索や `name LIKE "abc%"` などのプレフィックスフィルターを高速化します。

## 概要\{#overview}

### サポートされるデータ型\{#supported-data-types}

[VARCHAR フィールド](./use-string-field)のみです。JSON の文字列パスでは、[JSON インデックス](./json-indexing)で互換性のあるインデックスを選択してください。

<a id="queries-accelerated-by-trie"></a>
<a id="Queries-accelerated-by-TRIE"></a>

<a id="supported-filters"></a>
<a id="Supported-filters"></a>

### フィルターの高速化\{#filter-acceleration}

`TRIE` インデックスは、`VARCHAR` フィールドに対して次の条件を評価するのに役立ちます。式は例です。

| インデックスを使用できるフィルター | 式の例 |
| --- | --- |
| 等値（`==`、`!=`） | `category == "books"` |
| メンバーシップ（`in`、`not in`） | `category in ["books", "electronics"]` |
| プレフィックス一致 | `category LIKE "elec%"` |
| 範囲（`<`、`<=`、`>`、`>=`） | `category >= "a" and category < "m"` |

式の構文については、[基本演算子](./basic-filtering-operators)および[パターンマッチング](./pattern-match)を参照してください。

範囲の評価では、インデックス対象の複数の文字列を走査する場合があります。サフィックス、サブストリング、一般的な `LIKE`、および正規表現パターンも、インデックス対象の文字列に対して評価できますが、多数の異なる値を走査する必要がある場合があります。サブストリングまたは正規表現のワークロードでは、パターンの適用条件を使用して [NGRAM](./ngram-index-type) と比較してください。

<a id="best-practices"></a>
<a id="Best-practices"></a>

代表的な文字列の長さ、プレフィックス、結果件数を使用して、クエリレイテンシを比較してください。

<a id="usage-notes"></a>
<a id="Usage-notes"></a>

<Admonition type="info" icon="📘" title="Notes">

> これらはインデックスの機能であり、有効なフィルター式に対する制限ではありません。共通のルックアップ制約については、[スカラーインデックス](./scalar-index-overview#Filter-execution)を参照してください。`AND`、`OR`、`NOT`、および NULL テスト（`IS NULL`、`IS NOT NULL`）については、[基本演算子](./basic-filtering-operators)を参照してください。

</Admonition>


<a id="how-it-works"></a>
<a id="How-it-works"></a>

### TRIE の仕組み\{#how-trie-works}

<details>
<summary><strong>プレフィックスツリーのルックアップ処理を表示</strong></summary>

インデックスの構築中、Zilliz Cloud は文字列をプレフィックスツリーに挿入して永続化します。文字はエッジに沿って格納され、共有プレフィックスは 1 回だけ格納され、各終端ノードにはその文字列を持つエンティティ ID が記録されます。

等値検索では、ツリーをたどって対象文字列の終端ノードに到達します。プレフィックス検索では、プレフィックスノードを見つけて、そのサブツリーから ID を収集します。クエリエグゼキューターは、一致するエンティティ ID を受け取ります。

文字列またはプレフィックスノードへの走査はパターンの長さによって異なります。また、一致を返すには、関連付けられたエンティティ ID を収集する必要があります。

</details>

## TRIE インデックスの作成\{#create-a-trie-index}

`index_type` を `TRIE` に設定します。追加のインデックスパラメーターは不要です。

<Tabs groupId="code" defaultValue='python' values={[{"label":"Python","value":"python"},{"label":"Java","value":"java"},{"label":"Go","value":"go"},{"label":"Rust","value":"rust"},{"label":"C++","value":"c++"},{"label":"NodeJS","value":"javascript"},{"label":"cURL","value":"bash"}]}>
<TabItem value='python'>

```python
from pymilvus import MilvusClient

client = MilvusClient(uri="YOUR_CLUSTER_ENDPOINT")

# Assume you have defined a VARCHAR field named "category" in your collection schema

# Prepare index parameters
index_params = client.prepare_index_params()

# Add TRIE index on the "category" field
# highlight-start
index_params.add_index(
    field_name="category",     # Target VARCHAR field
    index_type="TRIE",         # Index type is TRIE
    index_name="category_trie" # Optional, name your index
)
# highlight-end

# Create the index on the collection
client.create_index(
    collection_name="product_catalog",
    index_params=index_params
)
```

</TabItem>

<TabItem value='java'>

```java
import io.milvus.v2.client.ConnectConfig;
import io.milvus.v2.client.MilvusClientV2;
import io.milvus.v2.common.IndexParam;
import io.milvus.v2.service.index.request.CreateIndexReq;
import java.util.Collections;

MilvusClientV2 client = new MilvusClientV2(ConnectConfig.builder()
        .uri("YOUR_CLUSTER_ENDPOINT")
        .build());

client.createIndex(CreateIndexReq.builder()
        .collectionName("product_catalog")
        .indexParams(Collections.singletonList(IndexParam.builder()
                .fieldName("category")
                .indexType(IndexParam.IndexType.TRIE)
                .indexName("category_trie")
                .build()))
        .build());
```

</TabItem>

```go
import (
    "context"
    "log"

    "github.com/milvus-io/milvus/client/v3/index"
    "github.com/milvus-io/milvus/client/v3/milvusclient"
)

ctx := context.Background()

cli, err := milvusclient.New(ctx, &milvusclient.ClientConfig{
    Address: "YOUR_CLUSTER_ENDPOINT",
})

if err != nil {
    log.Fatal("failed to connect to milvus server: ", err.Error())
}

_, err = cli.CreateIndex(ctx, milvusclient.NewCreateIndexOption("product_catalog", "category", index.NewTrieIndex()).WithIndexName("category_trie"))

if err != nil {
    log.Fatal("failed to create index: ", err.Error())
}
```

## インデックスの削除\{#drop-an-index}

既存のインデックスをコレクションから削除するには、`drop_index()` メソッドを使用します。

<Admonition type="info" icon="📘" title="Notes">

> スカラーインデックスを削除する際のリリース要件については、[スカラーインデックス](./scalar-index-overview#Drop-index-compatibility)を参照してください。

</Admonition>

<TabItem value='python'>

```python
client.drop_index(
    collection_name="product_catalog",   # Name of the collection
    index_name="category_trie"           # Name of the index to drop
```

```java
import io.milvus.v2.client.ConnectConfig;
import io.milvus.v2.client.MilvusClientV2;

        .build());

client.dropIndex(DropIndexReq.builder()

        .indexName("category_trie")
```
