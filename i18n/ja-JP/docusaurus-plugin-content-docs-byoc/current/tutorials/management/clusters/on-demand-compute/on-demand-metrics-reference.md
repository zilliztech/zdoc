# オンデマンドメトリクスリファレンス

このページでは、オンデマンドコンピュートデータベースとオンデマンドクラスターのメトリクスについて説明します。これらのメトリクスを使用して、コレクションのアクティビティ、コンピュートの準備状態、リクエストのパフォーマンス、リソースのアクティビティを監視できます。

## オンデマンドデータベースとコレクションのメトリクス\{#on-demand-database-and-collection-metrics}

次のメトリクスは、オンデマンドコンピュートデータベースのマネージドコレクションと外部コレクションについて、コンソールで使用できます。既存のドキュメントには、このリリースではこれらのデータベースメトリクスの Prometheus エクスポートがサポートされないと記載されています。アラートやその他のインテグレーションのサポートについては、別途確認してください。

### パフォーマンス\{#performance}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| QPS (Read) | 検索やクエリを含む、1 秒あたりの読み取りリクエスト数です。 | 読み取りトラフィックを監視し、レイテンシーと比較してください。 |
| Search NQ per Second | 検索リクエストが 1 秒あたりに処理するクエリベクトル数です。 | QPS と併せて検索ワークロード量を追跡してください。 |
| Latency (Read) (ms) | クライアントが読み取りリクエストを送信してから応答を受信するまでの経過時間です。平均レイテンシーと P99 レイテンシーが含まれます。 | 読み取りレイテンシーを追跡し、継続的な増加を調査してください。 |
| Request Failure Rate (Read) (%) | 1 秒あたりに失敗する読み取りリクエストの割合です。 | 読み取りリクエストの失敗を監視してください。対象のデプロイでのアラートサポートを確認してください。 |

### データ\{#data}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Entity Count | 単一挿入と一括挿入を含む、コレクションに挿入されたエンティティの総数です。 | 予期しない増加を調査し、ストレージとインデックス作成を計画してください。 |

<Admonition type="info" title="Note">

レビュー: 既存のオンラインドキュメントの文言では、読み取りレイテンシーをクライアントからサーバーを経由してクライアントに戻るまでの時間として説明しています。この定義を変更する前に、実際の測定範囲についてエンジニアリングチームと確認してください。これは、後述する Coordinator 側のクラスターリクエスト所要時間と混同しないでください。外部コレクションに関する Entity Count の文言も、実装に照らして検証してください。

</Admonition>

## オンデマンドクラスターメトリクス\{#on-demand-cluster-metrics}

これらのメトリクスは、個々のオンデマンドクラスターのコンピュートアクティベーション、リクエストのパフォーマンス、結果、CU のアクティビティを表します。これらは、オンデマンドコンピュートデータベースで使用できるコレクションレベルのメトリクスとは異なります。リクエストと実行を検査する手順については、[オンデマンドクラスターの監視](./monitor-on-demand-cluster) を参照してください。

所要時間のパーセンタイルはヒストグラムから推定されます。関連するサンプル数を使用して、どの程度のデータが表されているかを評価してください。異なる分布のパーセンタイルを加算、減算、または平均化しないでください。値が欠落している場合は、その測定値を利用できないことを意味し、必ずしもゼロであるとは限りません。

### 準備状態とリクエストのパフォーマンス\{#readiness-and-request-performance}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Compute readiness count | 準備完了として観測されたコンピュートアクティベーションの成功数です。複数のリクエストが待機している場合でも、物理的なアクティベーション 1 回につき 1 つのサンプルが寄与します。 | 準備状態のパーセンタイルを解釈する前に、サンプル数を確認してください。 |
| Compute readiness duration (P50/P95, seconds) | アクティベーションから、QueryNode が準備完了になり、リソースグループに参加するまでの時間です。 | 通常時と低速時のコンピュート起動時間を経時的に比較してください。 |
| コレクション readiness count | アクティベーション中にクエリ可能になった、観測されたコレクションの数です。同じアクティベーションが複数のコレクションサンプルに寄与する場合があります。 | 表されているコレクション準備状態のサンプル数を確認してください。 |
| Collection readiness duration (P50/P95, seconds) | アクティベーションから、観測されたコレクションがクエリ可能になるまでの時間です。この時間にはコンピュートの起動が含まれます。 | アクティベーション後、データがクエリ可能になるまでに要する時間を評価してください。 |
| Request duration (P50/P95, seconds) | 完了した Search、HybridSearch、Query リクエストの Coordinator 側の合計所要時間です。準備、待機、再試行が含まれます。クライアントのネットワーク時間とゲートウェイ時間は除外されます。 | バックエンド全体のレイテンシーを経時的に比較してください。 |
| Execution duration (P50/P95, seconds) | 実行に入った完了済みリクエストについて、トップレベルの実行試行の所要時間を累積したものです。スケジューリングと内部再試行が含まれ、準備の待機時間と外側の再試行間の間隔は除外されます。 | コンピュートおよびコレクションの準備とは別に、実行の動作を調査してください。 |
| Execution sample count | 実行に入った完了済みリクエストの数です。1 つのリクエストに対する複数のトップレベル試行は 1 つのサンプルを形成します。 | 実行時間の分布が表すデータ量を確認してください。 |
| Successful request duration by preparation state (P50/P95, seconds) | 成功したリクエストの合計所要時間を、コンピュートの起動またはコレクションの読み込みが観測されたかどうかでグループ化したものです。 | 準備が必要だったリクエストと、そうでなかったリクエストを比較してください。これは合計所要時間であり、待機時間やキャッシュヒットの指標ではありません。 |
| Successful search duration by operation and topK (sample count, P50/P95) | 成功した Search および HybridSearch リクエストのリクエスト所要時間と実行所要時間の分布を、操作および相互に排他的な topK 範囲でグループ化したものです。HybridSearch では最終的なランク上限が使用されます。 | 同様の検索ワークロードを比較し、各グループのサンプル数を確認してください。 |

### リクエストの結果とスループット\{#request-outcomes-and-throughput}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Completed requests | 完了した Search、HybridSearch、Query リクエストの数で、成功、失敗、タイムアウト、キャンセルの結果にグループ化されます。進行中のリクエストは除外されます。 | トラフィックと結果の変化を追跡してください。 |
| Error rate (%) | 失敗およびタイムアウトしたリクエストを、完了したすべてのリクエストで割ったものです。キャンセルされたリクエストは分母に含まれます。完了したリクエストがない場合、この値は利用できません。 | リクエスト結果の件数と併せて、増加を調査してください。 |
| QPS / QPM | 1 秒または 1 分あたりの完了リクエスト数で、完了したすべての結果が含まれます。 | スループットをレイテンシーおよび結果と比較してください。 |

### コンピュートリソースとライフサイクル\{#compute-resources-and-lifecycle}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Configured CU | 経時的な構成済みクエリ CU 容量です。クラスターが一時停止している間も、構成値は保持されます。 | 構成の変更をワークロードおよびレイテンシーと比較してください。 |
| Active CU | アクティビティイベントと請求イベントから再構築されたアクティブ CU の履歴です。一時停止中はゼロになります。CPU 使用率や準備完了ポッドの数ではありません。 | コンピュートがアクティブだった期間または一時停止していた期間を確認してください。 |
| Accepted starts | コンピュートレプリカがゼロから正の数への移行が承認された回数です。承認されたことは、コンピュートが準備完了であることを意味しません。 | アクティベーションの頻度を確認してください。 |
| Compute readiness count | コンピュートの準備完了状態に到達したアクティベーションの数です。 | イベントの発生時刻が異なることを考慮して、アクティベーション履歴と比較してください。 |
| Start timeout / cancellation | タイムアウトまたは別の停止操作により、コンピュートが準備完了になる前に終了したアクティベーションの数です。 | 準備完了状態に到達しなかったアクティベーションを調査してください。 |
| Accepted stop commands / completed stops | 承認された停止コマンドと、確認された物理的な停止です。コマンドは繰り返される場合があります。 | リソースのシャットダウン動作を確認してください。コマンド数は物理的な停止回数として扱わないでください。 |
| Stop duration (P50/P95, seconds) | 承認された停止コマンドから、対応するポッドがなくなったことが確認されるまでの時間です。観測の遅延が含まれます。 | リソースの解放が遅い場合に調査してください。 |
| Start and stop command failures | 失敗、タイムアウト、またはキャンセルされた開始コマンドおよび停止コマンドの呼び出し回数です。コマンドの結果だけでは、最終的なリソース状態を確定できません。 | 観測されたライフサイクルの結果と併せて、制御操作を調査してください。 |
