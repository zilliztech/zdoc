# Access Logs の概要

アクセスログは、クラスター上の検索およびクエリのアクティビティを記録します。独自の分析ツールと組み合わせて使用すると、リクエストのパフォーマンスとアプリケーションによるデータの使用状況を把握できます。

## アクセスログを使用する場面\{#when-to-use-access-logs}

- **頻繁に返されるエンティティを特定します。** 検索結果およびクエリ結果で最も多く出現するエンティティを確認できます。

- **リクエストのパフォーマンスを調査します。** 記録されたリクエストの所要時間を比較し、検索やクエリが遅い場合のパターンを特定します。

- **検索結果のスコアを調査します。** Search リクエストおよび HybridSearch リクエストで返される結果に関連付けられたスコアを分析します。

## アクセスログの仕組み\{#how-access-logs-work}

Zilliz Cloud が記録する内容とログの配信先を制御できます。

1. **記録する内容を選択します。** Search、HybridSearch、Query の各操作から選択します。サンプリングを調整してログ量を制御し、分析に必要なリクエストと結果の詳細を選択します。

1. **ログを転送します。** クラスターのプロジェクトでオブジェクトストレージまたは HTTPS Endpoint の統合を準備してから、アクセスログの転送を有効にします。統合を作成するだけでは、転送は開始されません。

1. **独自のシステムで分析します。** 受信側のサービスまたは分析ツールを使用して、配信されたログを保存し、クエリを実行し、可視化します。

## 考慮事項\{#what-to-consider}

- **ログ件数が不完全な場合があります。** サンプリングやエントリの破棄により、記録されたアクティビティにギャップが生じる可能性があります。リクエスト数と傾向を解釈する際は、これらのギャップを考慮してください。

- **返される結果はデータアクセスの一部のみを示します。** 返されたエンティティを数えると、それらが記録された結果に現れる頻度はわかりますが、リクエストの実行中に各エンティティが検査された頻度はわかりません。

<Admonition type="info" title="Note">

アクセスログと監査ログは、同じクラスターで同時に有効にすることはできません。スローログは別途設定します。実行時間のしきい値を超えるリクエストのみを調査する必要がある場合は、[スローログ](./configure-slow-logs) を参照してください。

</Admonition>
