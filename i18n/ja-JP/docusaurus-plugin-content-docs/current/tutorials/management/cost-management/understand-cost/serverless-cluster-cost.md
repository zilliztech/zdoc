# Serverless クラスターのコスト

Zilliz Cloud の Serverless クラスターは従量課金制を採用しており、主に読み取りおよび書き込み操作で消費されるリソースに対して課金されます。これにより、実際に処理されたワークロードに対してのみ料金が発生し、あらかじめ固定容量をプロビジョニングする必要はありません。

Serverless クラスターの総コストは、以下の構成要素の合計です。

- [読み取り](./serverless-cluster-cost#vector-database-costs-read) 操作および [書き込み](./serverless-cluster-cost#vector-database-costs-write) 操作のベクトルデータベースコスト

- [ストレージコスト](./serverless-cluster-cost#storage-cost)

上記の 2 つの主要な課金項目に加えて、以下のオプションの追加料金が発生する場合があります。

- [データ転送コスト](./data-transfer-cost)

- [監査ログコスト](./audit-log-cost)

## ベクトルデータベースのコスト（書き込み）\{#vector-database-costs-write}

書き込みコストは、[挿入](./insert-entities)、[アップサート](./upsert-entities)、[削除](./delete-entities) の各操作で消費されるコンピューティングリソースを測定します。

インポート操作および一括挿入操作では、コストは**発生しません**。

### コストの計算\{#cost-calculation}

```bash
Vector Database Cost (Write) = vCU Unit Price x Write vCU Usage 
```

- **vCU 単価:** 100 万 vCU あたり &#36;4 です。

- **書き込み vCU 使用量:** 書き込み操作で扱われるデータサイズに基づいて計算されます。

### 例\{#example}

以下の表は、Serverless クラスターに特定の量のデータを書き込む場合の vCU 使用量とコストの早見表です。

より大きなデータセットの場合は、vCU 使用量とコストを比例してスケーリングするだけです。たとえば、768 次元ベクトルを 1,000 万個書き込むと、約 750 万 vCU を使用し、コストは約 &#36;30 になります。

| **データサイズ（&ast;）** | **書き込み vCU 使用量（100 万）** | **書き込みコスト** |
| --- | --- | --- |
| 128 次元ベクトル 100 万個 | 0.125 | &#36;0.5 |
| 768 次元ベクトル 100 万個 | 0.75 | &#36;3 |
| 1536 次元ベクトル 100 万個 | 1.5 | &#36;6 |
| 2560 次元ベクトル 100 万個 | 2.5 | &#36;10 |

*&ast;上記の表のデータサイズにはスカラーは含まれません。*

*&ast;スキーマに複数のベクトルフィールドが含まれている場合、書き込みコストは線形に増加します。たとえば、スキーマに 2 つの 128 次元ベクトルフィールドがある場合、100 万個のエンティティを書き込む際の vCU 使用量は 0.125 × 2 = 0.25 となり、書き込みコストは約 &#36;0.5 × 2 = &#36;1 です。*

書き込み vCU 使用量とコストを正確に計算するには、以下のメトリクスを参照してください。

| **操作** | **vCU 使用量** |
| --- | --- |
| 挿入 | 挿入データ 1 KB = 0.25 vCU |
| 削除 | エンティティ 1 件あたり 1 vCU です。主キーによる削除では、リクエスト内の各主キーが、そのキーを持つエンティティが存在しない場合でも 1 vCU を消費します。フィルター式による削除では、一致するエンティティのみがカウントされます。 |
| アップサート | 更新されたデータのサイズと削除されたエンティティの数に基づいて計算されます。<br/>存在しないエンティティを削除する場合も 1 vCU を消費します。<br/>アップサートの vCU 使用量 = データ KB × 0.25 + アップサートされたエンティティ 1 件あたり 1 vCU（主キーが既に存在するかどうかに関係ありません）。たとえば、128 次元ベクトル 100 万個をアップサートすると約 0.125 + 1 = 112.5 万 vCU（&#36;4.50）を使用します。これは、同じデータを挿入する場合の 12.5 万 vCU（&#36;0.50）と比較されます。部分アップサート（partial_update）でも、エンティティ 1 件あたり 1 vCU が課金されます。 |

*&ast;データサイズは、SDK または RESTful API がエンコードした後の書き込みリクエストのサイズで、1 KB = 1,024 バイトです。使用量はリクエストごとに計算され、次の整数 vCU に切り上げられるため、すべての書き込みリクエストには少なくとも 1 vCU のコストがかかります。行をより大きなリクエストにまとめると、この切り上げによるオーバーヘッドを回避できます。RESTful API リクエストは、JSON 本文が大きい場合でも、同じデータに対して SDK（gRPC）リクエストと同じように課金されます。*

Serverless クラスターに 3 GB（3,145,728 KB）のエンティティを挿入し、その後 100,000 件のエンティティを削除したとします。

- `Insert operation vCU usage = 3,145,728 x 0.25 = 786,432 vCUs`

- `Delete operation vCU usage = 100,000 x 1 = 100,000 vCUs`

- `Total vCU usage = 100,000 + 786,432 = 886,432 vCUs`

- `Total vector database cost (write)  = 0.886432 x 4 = $3.55`

## ベクトルデータベースのコスト（読み取り）\{#vector-database-costs-read}

このコスト項目は、[検索](./single-vector-search)、[ハイブリッド検索](./hybrid-search)、[クエリ](./get-and-scalar-query) の各操作で消費されるリソースを測定します。

### コストの計算\{#cost-calculation}

```bash
Vector Database Cost (Read) = vCU Unit Price x Read vCU Usage 
```

- **vCU 単価:** 100 万 vCU あたり &#36;4

- **読み取り vCU 使用量:** 以下の 3 つの要因によって決まります。

    - 検索またはクエリのリクエスト数: 検索またはクエリの実行回数が多いほど、vCU 使用量が増加します。

    - 各検索またはクエリでスキャンされるデータのサイズ: スキャンされるデータが多いほど、vCU 使用量が増加します。

        *ヒント: 各検索またはクエリの際に、Zilliz Cloud はクラスター内のコレクション全体をスキャンします。検索またはクエリ中に [パーティションキー](./use-partition-key) をフィルターとして使用すると、Zilliz Cloud は指定されたパーティションキーに一致するコレクションの一部のみをスキャンするため、読み取り vCU 使用量全体を削減できます。*

    - 各検索またはクエリで返されるデータのサイズ: 返されるデータが多いほど、vCU 使用量が増加します。たとえば、検索でベクトルフィールドを含むすべてのフィールドを返すと、ID フィールドのみを返す検索よりもはるかに多くの vCU を消費します。

    <Admonition type="info" title="Notes">

    各読み取り操作には最低 6 vCU のコストがかかります。

    </Admonition>

### 例\{#example}

以下の表は、さまざまなデータ量に対して 100 万件の読み取りリクエストを行った場合の vCU 使用量とコストの例です。

| **スキャンデータサイズ（&ast;）** | **読み取り vCU 使用量（100 万）** | **読み取りコスト** |
| --- | --- | --- |
| 128 次元ベクトル 100 万個 | 5 | **&#36;24**<br/>（*&ast;各リクエストは 5 vCU を使用しますが、最低 6 vCU で課金されるため、100 万件のリクエストに対して合計 600 万の課金対象 vCU となります。*） |
| 768 次元ベクトル 100 万個 | 15 | &#36;60 |
| 768 次元ベクトル 500 万個 | 35 | &#36;140 |
| 768 次元ベクトル 1,000 万個 | 55 | &#36;220 |
| 1536 次元ベクトル 100 万個 | 25 | &#36;100 |
| 1536 次元ベクトル 1,000 万個 | 75 | &#36;300 |
| 1536 次元ベクトル 1 億個 | 290 | &#36;1160 |
| 1536 次元ベクトル 100 億個 | 1,495 | &#36;5980 |
| 2560 次元ベクトル 100 万個 | 30 | &#36;120 |

*&ast;上記の表のデータサイズにはスカラーは含まれません。*

上記の表から、データサイズが 100 万から 1,000 万、さらには 1 億に増加しても、vCU 使用量は比例して増加しないことがわかります。

## ストレージコスト\{#storage-cost}

ストレージコストはベクトルデータベースのコストとは別に課金され、以下によって異なります。

- クラスターのリージョン、クラスタータイプ、プロジェクトプラン

- ストレージ使用量

詳細は、[ストレージ](./storage-cost) を参照してください。
