# Access Logs の概要

アクセスログは、クラスター上の検索およびクエリのアクティビティを記録します。独自の分析ツールと組み合わせて使用することで、リクエストのパフォーマンスやアプリケーションによるデータの利用状況を把握できます。

## アクセスログを使用する場面\{#when-to-use-access-logs}

- **頻繁に返されるエンティティを特定します。** 検索結果やクエリ結果で最も頻繁に出現するエンティティを特定します。

- **リクエストのパフォーマンスを調査します。** 記録されたリクエスト所要時間を比較して、遅い検索やクエリのパターンを見つけます。

- **検索結果のスコアを確認します。** Search リクエストと HybridSearch リクエストで返された結果に関連するスコアを分析します。

## アクセスログの仕組み\{#how-access-logs-work}

Zilliz Cloud が記録する内容とログの送信先は、お客様が制御できます：

1. **記録する内容を選択します。** Search、HybridSearch、Query の各操作から選択します。サンプリングを調整してログ量を制御し、分析に必要なリクエストと結果の詳細を選択します。

1. **ログを転送します。** クラスターのプロジェクトでオブジェクトストレージまたは HTTPS Endpoint 統合を準備してから、アクセスログの転送を有効にします。統合を作成するだけでは、転送は開始されません。

1. **独自のシステムで分析します。** 受信側のサービスまたは分析ツールを使用して、配信されたログを保存し、クエリを実行し、可視化します。

## 考慮事項\{#what-to-consider}

- **ログの件数が不完全になる場合があります。** サンプリングやエントリの破棄によって、記録されるアクティビティに欠落が生じる可能性があります。リクエスト数や傾向を解釈する際は、こうした欠落を考慮してください。

- **返される結果はデータアクセスの一部のみを示します。** 返されたエンティティを数えることで、それらが記録済みの結果にどの程度の頻度で現れるかはわかりますが、リクエスト実行中に各エンティティがどの程度の頻度で検査されたかはわかりません。

<Admonition type="info" title="Note">

アクセスログと監査ログは、1 つのクラスターで同時に有効にすることはできません。スローログは別途構成します。所要時間のしきい値を超えるリクエストのみを調査する必要がある場合は、[スローログ](./configure-slow-logs) を参照してください。

</Admonition>
