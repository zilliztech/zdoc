# オンデマンドメトリクスリファレンス

このページでは、オンデマンドコンピュートデータベースとオンデマンドクラスターのメトリクスについて説明します。これらのメトリクスを使用して、コレクションのアクティビティ、コンピュートの準備状況、リクエストのパフォーマンス、リソースのアクティビティを監視します。

## オンデマンドデータベースとコレクションのメトリクス\{#on-demand-database-and-collection-metrics}

次のメトリクスは、オンデマンドコンピュートデータベース内のマネージドコレクションと外部コレクションのコンソールで使用できます。既存のドキュメントでは、このリリースのこれらのデータベースメトリクスについて Prometheus エクスポートがサポートされていないと記載されています。アラートやその他の統合のサポートについては、別途確認してください。

### パフォーマンス\{#performance}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| QPS (Read) | 検索とクエリを含む、1 秒あたりの読み取りリクエスト数です。 | 読み取りトラフィックを監視し、レイテンシと比較します。 |
| Search NQ per Second | 検索リクエストが 1 秒あたりに運ぶクエリベクトルの数です。 | QPS とあわせて検索ワークロード量を追跡します。 |
| Latency (Read) (ms) | クライアントが読み取りリクエストを送信してから応答を受信するまでの経過時間です。平均レイテンシと P99 レイテンシを含みます。 | 読み取りレイテンシを追跡し、継続的な増加を調査します。 |
| Request Failure Rate (Read) (%) | 1 秒あたりに失敗する読み取りリクエストの割合です。 | 読み取りリクエストの失敗を監視します。対象のデプロイメントでアラートがサポートされていることを確認してください。 |

### データ\{#data}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Entity Count | コレクションに挿入されたエンティティの合計数です。単一挿入と一括挿入を含みます。 | 予期しない増加を調査し、ストレージとインデックス作成を計画します。 |

<Admonition type="info" title="Note">

レビュー: 既存のオンライン上の表現では、読み取りレイテンシをクライアントからサーバー、そしてクライアントに戻るまでの時間として説明しています。この定義を変更する前に、実際の測定境界をエンジニアリング担当者と検証してください。これは、後述する Coordinator 側のクラスターリクエスト時間と混同しないでください。外部コレクションのエンティティ数の表現についても、実装と照らし合わせて検証してください。

</Admonition>

## オンデマンドクラスターのメトリクス\{#on-demand-cluster-metrics}

これらのメトリクスは、個々のオンデマンドクラスターのコンピュートアクティベーション、リクエストパフォーマンス、結果、CU アクティビティを表します。これらは、オンデマンドコンピュートデータベースで使用できるコレクションレベルのメトリクスとは異なります。リクエストと実行の確認方法については、[オンデマンドクラスターの監視](./monitor-on-demand-cluster) を参照してください。

継続時間のパーセンタイルはヒストグラムから推定されます。関連するサンプル数を使用して、どの程度のデータが表されているかを評価してください。異なる分布のパーセンタイルを加算、減算、または平均化しないでください。値が欠落している場合は測定値が利用できないことを意味し、必ずしもゼロではありません。

### 準備状況とリクエストパフォーマンス\{#readiness-and-request-performance}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Compute readiness count | 準備完了として観測された成功したコンピュートアクティベーションの数です。複数のリクエストが待機している場合でも、物理的なアクティベーションごとに 1 つのサンプルとしてカウントされます。 | 準備完了のパーセンタイルを解釈する前に、サンプル数を確認します。 |
| Compute readiness duration (P50/P95, seconds) | アクティベーションの開始から、QueryNode が準備完了になりリソースグループに参加するまでの時間です。 | 通常時と低速時のコンピュート起動時間を経時的に比較します。 |
| コレクション readiness count | アクティベーション中にクエリ可能になった、観測されたコレクションの数です。同じアクティベーションから複数のコレクションサンプルが生成される場合があります。 | コレクション準備完了サンプルがいくつ反映されているかを確認します。 |
| Collection readiness duration (P50/P95, seconds) | アクティベーションから、観測対象のコレクションがクエリ可能になるまでの時間です。この時間にはコンピュートの起動時間が含まれます。 | アクティベーション後にデータがクエリ可能になるまでの時間を評価します。 |
| Request duration (P50/P95, seconds) | 完了した Search、HybridSearch、Query リクエストの Coordinator 側の合計時間です。準備、待機、再試行を含みます。クライアントのネットワーク時間とゲートウェイ時間は含みません。 | 全体的なバックエンドレイテンシを経時的に比較します。 |
| Execution duration (P50/P95, seconds) | 実行に入った完了済みリクエストについて、トップレベルの実行試行の累積時間です。スケジューリングと内部再試行を含み、準備待機と外側の再試行間の間隔は含みません。 | コンピュートとコレクションの準備とは別に、実行の挙動を調査します。 |
| Execution sample count | 実行に入った完了済みリクエストの数です。1 つのリクエストに対する複数のトップレベル試行は、1 つのサンプルを構成します。 | 実行時間の分布が表すデータ量を確認します。 |
| Successful request duration by preparation state (P50/P95, seconds) | 成功したリクエストの合計時間を、コンピュートの起動またはコレクションの読み込みが観測されたかどうかでグループ化したものです。 | 準備が必要だったリクエストと、そうでなかったリクエストを比較します。これは合計時間であり、待機時間やキャッシュヒットの指標ではありません。 |
| Successful search duration by operation and topK (sample count, P50/P95) | 成功した Search および HybridSearch リクエストのリクエスト時間と実行時間の分布を、操作と相互に排他的な topK 範囲でグループ化したものです。HybridSearch では最終的なランク上限が使用されます。 | 類似した検索ワークロードを比較し、各グループのサンプル数を確認します。 |

### リクエスト結果とスループット\{#request-outcomes-and-throughput}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Completed requests | 完了した Search、HybridSearch、Query リクエストの数で、成功、失敗、タイムアウト、キャンセルの結果に分類されます。進行中のリクエストは含まれません。 | トラフィックと結果の変化を追跡します。 |
| Error rate (%) | 失敗したリクエストとタイムアウトしたリクエストを、完了したすべてのリクエストで割った値です。キャンセルされたリクエストも分母に含まれます。完了したリクエストがない場合、この値は利用できません。 | リクエスト結果の件数とあわせて、増加を調査します。 |
| QPS / QPM | 1 秒あたりまたは 1 分あたりの完了リクエスト数です。完了したすべての結果を含みます。 | スループットをレイテンシと結果と比較します。 |

### コンピュートリソースとライフサイクル\{#compute-resources-and-lifecycle}

| メトリクス | 説明 | 推奨される対応 |
| --- | --- | --- |
| Configured CU | 時間の経過に伴う構成済みのクエリ CU 容量です。クラスターが一時停止している間も、構成済みの値は維持されます。 | 構成の変更をワークロードとレイテンシと比較します。 |
| Active CU | アクティビティイベントと請求イベントから再構築されたアクティブ CU の履歴です。一時停止中はゼロになります。CPU 使用率や、準備完了の Pod の数ではありません。 | コンピュートがアクティブまたは一時停止していた時点を確認します。 |
| Accepted starts | コンピュートレプリカがゼロから正の数へ移行した承認済みの回数です。承認されたことは、コンピュートが準備完了であることを意味しません。 | アクティベーションの頻度を確認します。 |
| Compute readiness count | コンピュートの準備完了に到達したアクティベーションの数です。 | イベントの発生時刻が異なることを考慮して、アクティベーション履歴と比較します。 |
| Start timeout / cancellation | タイムアウトまたは別の停止操作により、コンピュートが準備完了になる前に終了したアクティベーションの数です。 | 準備完了に到達しなかったアクティベーションを調査します。 |
| Accepted stop commands / completed stops | 承認された停止コマンドと、確認された物理的な停止です。コマンドは繰り返し送信される場合があります。 | リソースのシャットダウン動作を確認します。コマンド数は物理的な停止回数として扱わないでください。 |
| Stop duration (P50/P95, seconds) | 承認された停止コマンドから、対応する Pod がなくなったことを確認するまでの時間です。観測の遅延を含みます。 | リソースの解放に時間がかかっている場合を調査します。 |
| Start and stop command failures | 失敗、タイムアウト、またはキャンセルされた起動および停止コマンド呼び出しの数です。コマンドの結果だけでは、最終的なリソース状態を確定できません。 | 観測されたライフサイクル結果とあわせて、制御操作を調査します。 |
