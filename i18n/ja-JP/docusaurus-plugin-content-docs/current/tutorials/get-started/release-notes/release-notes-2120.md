# リリースノート (2024年12月26日)

このリリースでは、Zilliz Cloud の BYOC ソリューション全体のセキュリティ、パフォーマンス、および使いやすさを向上させる重要な機能強化が導入されています。グローバルな mmap 戦略が実装され、フィールドレベルとインデックスレベルの両方でカスタマイズ可能な設定が提供されることで、検索パフォーマンスを維持しながらコレクション容量を増加させることが可能になりました。Milvus をベースに、Zilliz Cloud はクラスター内でのデータベース作成をサポートし、より良いデータ管理とマルチテナンシーのためにコレクションレベルのロールベースアクセス制御（RBAC）を提供するようになりました。さらに、検索精度の設定が洗練され、検索精度とパフォーマンスを効果的に最適化するためのリコール率推定機能と組み合わされるようになりました。

## Milvus 互換性\{#milvus-compatibility}

このリリースは **Milvus 2.4.x** と互換性があります。

## BYOC - データセキュリティと権限制御のための全く新しいソリューション\{#byoc-a-brand-new-solution-for-data-security-and-permission-control}

Zilliz Cloud のエンタープライズ導入が進むにつれ、データセキュリティガバナンスと権限制御への関心が高まっています。そのため、このリリースでは、ベクトルデータベースサービスにおけるデータセキュリティとサービス品質の厳格な要件を満たすため、全く新しい Bring-Your-Own-Cloud（BYOC）ソリューションを導入しました。このソリューションは以下を保証します：

- **セキュアな通信**: コントロールプレーンとデータプレーン間の通信は、送信専用ポート 443 を介してのみ行われ、堅牢で安全な接続を確保します。

- **最適化された権限**: デプロイメントおよび運用タスクに必要な権限設定が最小化され、きめ細かく設定されるようになり、セキュリティと管理の容易性が向上しました。完全な権限リストについては [こちら](/docs/byoc/permissions-in-roles) をご覧ください。

詳細については、[BYOC 概要](/docs/byoc/byoc-intro) および [AWS への BYOC デプロイ](/docs/byoc/deploy-byoc-aws) を参照してください。

## 新しいリージョンの提供: GCP us-central1 (Iowa)\{#new-region-available-gcp-us-central1-lowa}

Zilliz Cloud は、GCP us-central1 リージョン（Iowa）で利用可能になりました。これにより、米国中部のユーザーに対して、レイテンシとパフォーマンスが向上します。

利用可能なすべてのリージョンの詳細な価格情報については、[料金ページ](https://zilliz.com/pricing) をご覧ください。

## データベースレイヤーのサポート\{#support-for-database-layer}

Zilliz Cloud には、クラスターとコレクションの間に位置するデータベースレイヤーが追加され、データを効率的に管理・整理し、マルチテナンシーを実現する方法が提供されるようになりました。この構造では、データベースはデータを整理・管理するための論理単位です。ユーザーは複数のデータベースを作成し、異なるアプリケーションやテナント間でデータを論理的に分離することで、データセキュリティを強化し、マルチテナンシーを実現できます。[データベースの詳細](/docs/database) をご覧ください。

## 拡張データ容量のための mmap サポート\{#mmap-support-for-expanded-data-capacity}

このリリースでは、Zilliz Cloud に `mmap` サポートが導入され、最大 3 倍のデータを最適に提供できるようになりました。`mmap` は、ディスクに保存された大きなファイルへの直接メモリアクセスを可能にし、Zilliz Cloud がインデックスとデータをメモリとディスクの両方に保存できるようにします。この設定は、アクセス頻度に基づいてデータ配置を最適化し、検索パフォーマンスを維持しながらコレクションのストレージ容量を大幅に拡張します。

専用クラスターのユーザーは、ワークロード要件に基づいて `mmap` 設定を完全にカスタマイズできます。各コレクション内のベクトルデータ、スカラーデータ、およびスカラーインデックスの `mmap` 戦略を柔軟に制御できます。グローバルな mmap 戦略の詳細については、[mmap の使用](./use-mmap) をお読みください。

## コレクションレベル RBAC サポート\{#collection-level-rbac-support}

このリリースでは、コレクションレベルのロールベースアクセス制御（RBAC）のサポートが導入され、ユーザーがコレクションレベルで権限を管理し、マルチテナンシー分離を実施できるようになりました。

3 つの組み込みコレクションレベル特権グループが利用可能になりました：

- **CollectionReadOnly (COLL_RO)**: コレクションデータへの読み取り専用アクセスを付与します。

- **CollectionReadWrite (COLL_RW)**: コレクションデータへの読み取りおよび書き込みアクセスを付与します。

- **CollectionAdmin (COLL_ADMIN)**: コレクションデータへの読み取りおよび書き込みアクセスに加え、コレクションを管理する権限を付与します。

詳細については、[コレクションレベル特権グループ](./cluster-privileges#collection-level-privilege-groups) をご覧ください。

## 高リコール検索\{#high-recall-search}

Zilliz Cloud では、検索精度を制御してベクトル検索を最適化するための `level` という検索パラメータが導入されました。このパラメータは **1 から 10** の範囲で、デフォルトは **1** です。このパラメータを調整することで、ユーザーは検索リコールとパフォーマンスのバランスを取ることができます：

- **デフォルト値 (level=1)**: 通常のケースで 90% 以上のリコールを提供し、最適な検索パフォーマンスを維持します。

- **高リコール検索 (level=6~10)**: 高いリコール率（例：99% 以上）が必要なシナリオでは、ユーザーはパラメータを **6** から **10** の間に設定するか、パフォーマンスがそれほど重要でない場合は **10** を選択できます。

この柔軟性により、ユーザーは特定の要件に合わせて検索動作を調整し、精度と速度の間で望ましいバランスを実現できます。詳細については、[`level` パラメータの使用](./single-vector-search#use-level) をご覧ください。

## リコール率推定\{#recall-rate-estimation}

検索時にリコール率を推定する機能が導入されました。`search_params` の `enable_recall_calculation` パラメータを有効にし、`true` に設定することで、システムが推定したリコール率を検索結果の一部として受け取ることができます。

リコール率推定と `level` パラメータを組み合わせることで、ユーザーはアプリケーションに対して望ましいリコール率を達成するための適切な `level` 設定を簡単に特定できます。詳細については、[リコール率の取得](./single-vector-search#get-recall-rate) を参照してください。
