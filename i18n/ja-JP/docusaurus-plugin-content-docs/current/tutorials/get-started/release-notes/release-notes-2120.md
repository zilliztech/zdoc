# リリースノート（2024年12月26日）

今回のリリースでは、Zilliz Cloud が BYOC ソリューション全体におけるセキュリティ、パフォーマンス、および使いやすさを大幅に強化しました。グローバル mmap 戦略が新たに実装され、フィールドレベルおよびインデックスレベルでカスタマイズ可能な設定が可能となり、検索パフォーマンスを維持しながらコレクションの容量を拡張できます。Milvus を基盤として、Zilliz Cloud はクラスター内でのデータベース作成をサポートし、コレクションレベルのロールベースアクセス制御（RBAC）を提供することで、データ管理とマルチテナンシーをより効果的に実現します。さらに、検索精度の設定が洗練され、リコール率推定機能と連携することで、検索の正確性とパフォーマンスを効率よく最適化できるようになりました。

## Milvus 互換性\{#milvus-compatibility}

このリリースは **Milvus 2.4.x** と互換性があります。

## BYOC - データセキュリティと権限制御のためのまったく新しいソリューション\{#byoc-a-brand-new-solution-for-data-security-and-permission-control}

Zilliz Cloud のエンタープライズ採用が進むにつれ、データセキュリティガバナンスと権限制御への関心が高まっています。そのため、今回のリリースでは、ベクトルデータベースサービスにおけるデータセキュリティとサービス品質に対する厳しい要件を満たすための、まったく新しい Bring-Your-Own (BYOC) ソリューションを導入しました。このソリューションは以下を保証します。

- **セキュアな通信**: コントロールプレーンとデータプレーン間の通信は、すべてアウトバウンドポート 443 経由で行われるようになり、堅牢かつ安全な接続を確保します。

- **最適化された権限**: デプロイおよび運用タスクに必要な権限設定が最小限かつ細分化され、セキュリティと管理の容易さが向上します。権限の完全な一覧については、[こちら](/docs/byoc/permissions-in-roles)をご確認ください。

詳細については、[BYOC 概要](/docs/byoc/byoc-intro)および[AWS への BYOC デプロイ](/docs/byoc/deploy-byoc-aws)をご参照ください。

## 新しいリージョンが利用可能：GCP us-central1（アイオワ）\{#new-region-available-gcp-us-central1-lowa}

Zilliz Cloud が GCP us-central1 リージョン（アイオワ）で利用可能になり、米国中部にお住まいのユーザーのレイテンシとパフォーマンスが向上します。

利用可能なすべてのリージョンの詳細な価格情報については、[料金ページ](https://zilliz.com/pricing)をご覧ください。

## データベースレイヤーのサポート\{#support-for-database-layer}

Zilliz Cloud は、クラスターとコレクションの間に位置するデータベースレイヤーを新たにサポートしました。これにより、データの効率的な管理・整理とマルチテナンシーの実現が可能になります。この構造において、データベースはデータを整理・管理するための論理単位です。ユーザーは複数のデータベースを作成し、異なるアプリケーションやテナント間でデータを論理的に分離することで、データセキュリティを強化し、マルチテナンシーを実現できます。[データベースについて詳しく知る](/docs/database)

## 拡張されたデータ容量のための mmap サポート\{#mmap-support-for-expanded-data-capacity}

今回のリリースでは、Zilliz Cloud に `mmap` サポートが追加され、最適な状態で最大 3 倍のデータを処理できるようになりました。`mmap` はディスク上に保存された大規模ファイルへの直接メモリアクセスを可能にし、Zilliz Cloud がインデックスおよびデータをメモリとディスクの両方に格納できるようにします。この仕組みにより、アクセス頻度に基づいてデータ配置を最適化し、コレクションのストレージ容量を大幅に拡張しながらも検索パフォーマンスを維持します。

専用クラスターのユーザーは、ワークロード要件に応じて `mmap` 設定を完全にカスタマイズできます。各コレクション内で、ベクトルデータ、スカラーデータ、スカラーインデックスそれぞれに対して柔軟に `mmap` 戦略を制御可能です。グローバル mmap 戦略の詳細については、[mmap の使用方法](./use-mmap)をご覧ください。

## コレクションレベル RBAC サポート\{#collection-level-rbac-support}

今回のリリースでは、コレクションレベルのロールベースアクセス制御（RBAC）をサポートし、ユーザーがコレクションレベルで権限を管理し、マルチテナンシー分離を実施できるようになりました。

現在、以下の 3 つの組み込みコレクションレベル特権グループが利用可能です。

- **CollectionReadOnly (COLL_RO)**: コレクションデータへの読み取り専用アクセスを許可します。

- **CollectionReadWrite (COLL_RW)**: コレクションデータへの読み取りおよび書き込みアクセスを許可します。

- **CollectionAdmin (COLL_ADMIN)**: コレクションデータへの読み取りおよび書き込みアクセスに加え、コレクションの管理権限を付与します。

詳細については、[コレクションレベル特権グループ](./cluster-privileges#collection-level-privilege-groups)をご参照ください。

## 高リコール検索\{#high-recall-search}

Zilliz Cloud では、検索精度を制御することでベクトル検索を最適化する `level` という検索パラメータを導入しました。このパラメータは **1 から 10** の範囲で設定でき、デフォルト値は **1** です。このパラメータを調整することで、ユーザーは検索リコールとパフォーマンスのバランスを取ることができます。

- **デフォルト値（level=1）**: 典型的なケースで 90% 以上のリコールを提供しつつ、最適な検索パフォーマンスを維持します。

- **高リコール検索（level=6～10）**: リコール率が非常に高い（例：99% 以上）必要があるシナリオでは、パラメータを **6 から 10** の間に設定できます。パフォーマンスがそれほど重要でない場合は **10** を選択することも可能です。

この柔軟性により、ユーザーは自身の要件に合わせて検索動作を調整し、精度と速度の望ましいバランスを実現できます。詳細については、['level' パラメータの使用方法](./single-vector-search#use-level)をご参照ください。

## リコール率推定\{#recall-rate-estimation}

検索中のリコール率を推定する機能を新たに導入しました。`search_params` 内の `enable_recall_calculation` パラメータを `true` に設定すると、検索結果の一部としてシステムによるリコール率の推定値を受け取ることができます。

リコール率推定機能と `level` パラメータを組み合わせることで、ユーザーはアプリケーションに必要なリコール率を達成するための適切な `level` 設定を簡単に特定できます。詳細については、[リコール率の取得方法](./single-vector-search#get-recall-rate)をご参照ください。
