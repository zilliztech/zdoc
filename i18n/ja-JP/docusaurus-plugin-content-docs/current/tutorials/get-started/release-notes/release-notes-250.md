# リリースノート（2024年1月18日）

Zilliz Cloud では、データインポート機能のユーザーエクスペリエンスを最適化し、階層的な権限を持つ API キーを改良するとともに、メトリクスおよびアラート機構を強化しました。

## Milvus 互換性\{#milvus-compatibility}

このリリースは **Milvus 2.2.x** および **Milvus 2.3.x (Beta)** と互換性があります。

## データインポート\{#data-import}

最新リリースでは、Parquet データ形式のサポートを開始しました。ユーザーエクスペリエンスをさらに向上させるため、PyMilvus writer ユーティリティを導入しました。この強力なツールにより、ユーザーは JSON または Parquet 形式のファイルを簡単に作成し、シームレスにデータをインポートできます。詳細および新たな可能性については、[データインポート](./data-import) をご確認ください。

## APIキー\{#api-key}

今回のリリースでは、[APIキー](./manage-api-keys) の統合デザインを導入しました。各ユーザーは、単一の統合 API キーを使用して Zilliz Cloud プラットフォームおよび複数のクラスターにアクセスできます。

Zilliz Cloud の権限設計は RBAC（ロール-Based Access Control：ロールベースアクセス制御）の原則に従い、オペレーション層とデータ層の2層で構成されています。オペレーション層では、クラスター、プロジェクト、ユーザー、請求（請求）などのリソースに対する操作権限をロールで管理します。一方、データ層では、データの追加・削除・更新・照会といった操作能力を制御します。

![V6ZhbOu0go1AORx0dxFcELQ3ndd](https://zdoc-images.s3.us-west-2.amazonaws.com/v6zhbou0go1aorx0dxfcelq3ndd.png "V6ZhbOu0go1AORx0dxFcELQ3ndd")

オペレーション層では、Zilliz Cloud は4種類のロールをサポートしており、そのうち組織オーナー（組織オーナー）、プロジェクトオーナー（Project オーナー）、プロジェクトメンバー（Project Member）がよく使用される3つのロールです。

- 組織オーナー（組織オーナー）: 組織全体の設定、支払い方法および請求（請求）の管理、APIキー、組織内のすべてのプロジェクトおよび関連リソースに対する完全な管理権限を持ちます。

- プロジェクトオーナー（Project オーナー）: プロジェクト設定、プロジェクト内のすべてのクラスター、APIキー、およびその他の関連リソースに対する完全な管理権限を持ちます。

- プロジェクトメンバー（Project Member）: プロジェクト内のすべてのクラスターに対して読み書き権限を持ち、クラスターの詳細を表示したり、コレクションやインデックスを管理したりできます。

データ層では、Zilliz Cloud は Admin、読み取り専用（読み取り専用）、読み書き（読み書き）の3つの組み込みロールを提供し、データの管理・書き込み・読み取り権限を制御します。また、ユーザーはカスタムロールを作成することも可能です。これらのカスタムロールでは、特定のコレクション、パーティション、または操作に対する権限を定義でき、Zilliz Cloud 利用時に最小限のデータ権限の原則を確保できます。詳細については、*ドキュメント*をご参照ください。

## メトリクスとアラート\{#metrics-and-alert}

今回のリリースでは、[メトリクスボードおよびアラートシステム](./metrics-and-alerts) をリファクタリングしました。新バージョンでは、以下の包括的なメトリクスを監視できます。

- リソース使用率メトリクス: CU（Compute Unit）計算リソース使用率、CU容量使用率（fullness）、ストレージ全体の使用量を詳細に把握できます。

- パフォーマンスメトリクス: 検索/クエリのスループットおよびレイテンシ、データ挿入の効率（スループットおよびレイテンシ）、リクエスト失敗率などの重要なパフォーマンス指標を追跡できます。

- データメトリクス: コレクション数、エンティティ総数、検索のためにロードされたエンティティ数、インデックス済みエンティティ数に関するインサイトを得られます。

さらに、強化されたアラートシステムにより、上記すべてのメトリクスに対してカスタマイズされたアラートルールを設定できます。たとえば、1秒あたりのクエリ数（QPS）が1000を超えた場合や、CUの使用率（fullness）が70%を超えた場合などにアラートを発行し、システムの健全性とパフォーマンスを常に把握・対応できるようになります。

## 機能強化\{#enhancements}

今回のリリースには以下の機能強化も含まれています。

- 複数の Web コンソールページのユーザーエクスペリエンスを改善。
- 安定性の向上: 既知の問題を修正し、サービスの信頼性をさらに高めました。
