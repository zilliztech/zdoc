# リリースノート (2024年1月18日)

Zilliz Cloud は、データインポート機能のユーザー体験を最適化し、階層的な権限を持つ APIキー を洗練させ、メトリクスとアラートの仕組みを強化しました。

## Milvus 互換性\{#milvus-compatibility}

このリリースは **Milvus 2.2.x** および **Milvus 2.3.x (Beta)** と互換性があります。

## データインポート\{#data-import}

最新リリースで Parquet データ形式のサポートを発表できることを嬉しく思います。ユーザー体験を向上させるため、PyMilvus writer ユーティリティを導入しました。これは、シームレスなデータインポートのために JSON または Parquet 形式のファイルを簡単に作成するのを支援する強力なツールです。詳細を確認し、新しい可能性を探索するには、[データインポート](./data-import) をご覧ください。

## APIキー\{#api-key}

このリリースでは、Zilliz Cloud は [APIキー](./manage-api-keys) の統一デザインを導入しました。各ユーザーは、単一の統一された APIキー を使用して、Zilliz Cloud プラットフォームおよび複数のクラスタにアクセスできます。

Zilliz Cloud の権限設計は、RBAC（ロールベースアクセスコントロール）の原則に従っており、オペレーションレイヤーとデータレイヤーの2つのレイヤーに分かれています。オペレーションレイヤーでは、ロールはクラスタ、プロジェクト、ユーザー、請求などのリソースの運用権限を管理します。データレイヤーでは、ロールはデータの追加、削除、変更、クエリの機能を制御することに焦点を当てています。

![V6ZhbOu0go1AORx0dxFcELQ3ndd](https://zdoc-images.s3.us-west-2.amazonaws.com/v6zhbou0go1aorx0dxfcelq3ndd.png "V6ZhbOu0go1AORx0dxFcELQ3ndd")

オペレーションレイヤーでは、Zilliz Cloud は4種類のロールをサポートしており、そのうち 組織オーナー、プロジェクトオーナー、プロジェクトメンバー は3つの一般的に使用されるロールです：

- 組織オーナー: 組織設定、支払い方法と請求の管理、APIキー、組織内のすべてのプロジェクト、および関連リソースを含む、組織に対する完全な管理権限を持ちます。

- プロジェクトオーナー: プロジェクト設定、プロジェクト内のすべてのクラスタ、APIキー、およびその他の関連リソースを含む、プロジェクトに対する完全な管理権限を持ちます。

- プロジェクトメンバー: プロジェクト内のすべてのクラスタに対する読み書き権限を持ち、クラスタの詳細を表示し、コレクションとインデックスを管理できます。

データレイヤーでは、Zilliz Cloud はデータの管理、書き込み、読み取り権限を制御するために、Admin、読み取り専用、読み書き の3つの組み込みロールを提供しています。Zilliz Cloud では、ユーザーが カスタムロール を作成できます。これらの カスタムロール は、特定のコレクション、パーティション、または操作に対する権限を定義でき、Zilliz Cloud を使用する際に最小限のデータ権限の原則を確保します。詳細については、*ドキュメント* を参照してください。

## メトリクスとアラート\{#metrics-and-alert}

このリリースでは、[メトリクスボードとアラートシステム](./metrics-and-alerts) をリファクタリングしました。新しいバージョンでは、包括的なメトリクスの範囲を監視する機能を持っています：

- リソース使用メトリクス: CU（Compute Unit）計算リソース使用率、CU容量 使用率（満杯度）、および全体的なストレージ使用量の詳細な表示が含まれます。

- パフォーマンス メトリクス: 検索/クエリのスループットとレイテンシ、データ挿入の効率性（スループットとレイテンシの両方）、およびリクエスト失敗率などの重要な パフォーマンス 指標を追跡します。

- データ メトリクス: コレクションの数、エンティティの総数、検索用にロードされたエンティティの数、およびインデックス付きエンティティの数に関する洞察を得られます。

さらに、強化されたアラートシステムでは、前述のすべてのメトリクスに対してカスタマイズされたアラートルールを設定できます。これは、Query Per Second（QPS）レートが1000を超えた場合、または CU 満杯度が70%を超えた場合などのシナリオでアラートを作成できることを意味し、システムの健全性と パフォーマンス について常に情報を得て、積極的に対応できることを確保します。

## 機能強化\{#enhancements}

このリリースには、一連の機能強化も含まれています：

- いくつかの Web コンソールページの体験を改善しました。

- 安定性の強化: 既知の問題に対処し、サービスの信頼性をさらに向上させました。
