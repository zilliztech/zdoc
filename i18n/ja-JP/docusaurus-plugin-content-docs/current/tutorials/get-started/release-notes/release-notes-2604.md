        ## グローバルクラスター\{#global-cluster}

        グローバルクラスター は、洗練されたプラットフォーム機能により、リージョンレベルのディザスターリカバリフェイルオーバーを完全にサポートするようになりました。

        - フェイルオーバー: プライマリークラスターが利用できなくなった場合、いつでもフェイルオーバーを実行できます。フェイルオーバー後、新しいセカンダリークラスターが自動的に再作成されます。

        - 独立したレプリカスケーリング: プライマリークラスターとセカンダリークラスターはそれぞれ独立して、レプリカ数、ダイナミックスケーリング、およびスケジュールスケーリングの設定を管理できるようになりました。

        - 簡単な変換: グローバルクラスター と通常の専用クラスターの間でシームレスに変換できるようになりました。

        - 監査ログ: グローバルクラスター のトポロジ変更（作成、スイッチオーバー、フェイルオーバー、セカンダリー管理を含む）がすべて監査ログに記録されるようになりました。詳細については、[グローバルクラスター の解説](./global-cluster-explained) および [スイッチオーバーとフェイルオーバー](./switchover-and-failover) を参照してください。

        ## コレクションレベルのメトリクス\{#collection-level-metrics}

        以下のメトリクスがコレクションレベルの内訳をサポートするようになり、個々のコレクションのパフォーマンス問題の特定や容量計画に役立ちます。

        - QPS（読み取り/書き込み）

        - レイテンシ（読み取り/書き込み、平均および P99）

        - エンティティ数

        - ロードされたエンティティ

        コンソール UI、Prometheus エンドポイント、または RESTful API からコレクションレベルのメトリクスにアクセスできます。詳細については、[メトリクスリファレンス](./metrics-alerts-reference) および [Prometheus との統合](./prometheus-monitoring) を参照してください。

        ## アクセスログ | PUBLIC\{#access-logs}

        Zilliz Cloud は、クラスター上のクエリレベルのアクティビティ（検索、ハイブリッド検索、クエリ）をキャプチャするためのアクセスログをサポートし、パフォーマンス分析とビジネスインサイトを提供するように設計されています。主な機能は以下の通りです。

        - **構成可能なサンプリング** — 精度とストレージコストのバランスを取ります（例：1% のサンプリングレート）。

        - **カスタマイズ可能な出力フィールド** — エントリごとのログの詳細度を制御します。

        - **ホットデータの特定** — 返されたプライマリキーを分析して、頻繁にアクセスされるレコードを特定します。

        - **構造化された JSON Lines 形式** — あらゆる分析パイプラインに対応しています。詳細については、[アクセスログ](./access-logs) を参照してください。

        ## メンテナンスウィンドウ\{#maintenance-window}

        メンテナンスウィンドウのエクスペリエンスが再設計され、最低 4 時間の期間延長、アップグレードの 7 日前・3 日前・1 日前にメールおよびコンソール内通知、アップグレードを 7 日間延期する機能、そしてすべてのビジネスクリティカルプランおよびエンタープライズプランでの利用が可能になりました。詳細については、[メンテナンスウィンドウの設定](./organization-settings#set-up-preferred-maintenance-window) を参照してください。

        ## クラスター管理者ロール\{#cluster-admin-role}

        新しいクラスター管理者ロールにより、プロジェクトレベルの管理者権限を持たずに、特定のクラスターに対する運用アクセス権限をチームメンバーに付与できます。

        - クラスター運用: クラスター管理者は、スケーリング、一時停止/再開、バックアップ/リストア、DB ユーザー管理などの日常的な運用タスクを実行できます。

        - クラスターごとのスコーピング: このロールは特定のクラスターに割り当てることができ、環境やワークロード全体できめ細かい職務分掌を実現します。

        - 注: カスタマイズされた API キーは現在、クラスター管理者ロールをサポートしていません。詳細については、[プロジェクトユーザーの管理](./project-users) を参照してください。

        ## Zilliz Cloud BYOC がティアードストレージクラスターをサポート\{#zilliz-cloud-byoc-supports-tiered-storage-cluster}

        BYOC デプロイメントでティアードストレージクラスターを作成できるようになりました。これをサポートするため、BYOC プロジェクトではティアードクエリノードグループの構成が導入され、ティアードストレージクラスターのクエリノードに対してインスタンスタイプ、ノード数、スケーリングを独立して設定できるようになりました。詳細については、[AWS での BYOC のデプロイ](/docs/byoc/deploy-byoc-aws) を参照してください。

        ## 機能強化\{#enhancements}

        - コレクションデータプレビューを、プライマリキー、数値、またはその他のスカラーフィールドに基づいて昇順または降順でソートできるようになりました。詳細については、[コレクションの管理（コンソール）](./manage-collections-console) の「コレクションデータのプレビュー」セクションを参照してください。
