# データ：外部コレクションとマネージドコレクション

コレクションは、固定された列と可変の行を持つ 2 次元テーブルです。各列はフィールドを表し、各行はエンティティを表します。Zilliz Cloud では、コレクションには**マネージド**と**外部**の 2 種類があります。どちらを選択するかは、データライフサイクルのどの段階にあるかによって異なります。

## 概要\{#overview}

### マネージドコレクション\{#managed-collection}

マネージドコレクションは、Zilliz Cloud クラスターのストレージにデータを保存します。継続的な挿入、更新、リアルタイムクエリ、予測可能な低遅延でのサービングなど、全機能セットを利用できます。オンライン状態を維持し、データを変更する必要がある本番アプリケーションを実行している場合、これが適しています。

### 外部コレクション\{#external-collection}

外部コレクションでは、データを元の場所（S3、Parquet などのオープン形式）に残したままにします。Zilliz Cloud は、外部ファイルをセグメントにグループ化する**マニフェスト**を生成することで、これらのファイルに接続します。ファイルが変更された場合は、**Refresh**を実行してマニフェストを更新します。インデックスが必要な場合、**Build Index**は何も Zilliz Cloud クラスターのストレージにコピーすることなく、マニフェストを通じてデータを読み取ります。外部コレクションは読み取り専用です。

## 主要概念\{#key-concepts}

### スキーマとフィールド\{#schema-and-fields}

スキーマはコレクションの構造を定義します。各フィールドには、データ型やベクトル次元などの制約があります。挿入するすべてのエンティティはスキーマに一致する必要があります。

一部のフィールドをオプションにしたい場合は、それらを nullable に設定するか、デフォルト値を設定するか、動的フィールドを有効にしてください。

<Admonition type="info" icon="📘" title="Notes">

<p>外部コレクションでは、動的フィールドを使用したり、スキーマに関数を定義したりすることはできません。一度作成されると、スキーマはロックされます。</p>

</Admonition>

### プライマリキーと AutoId\{#primary-key-and-autoid}

プライマリフィールドは、あるエンティティを別のエンティティと区別します。その値はグローバルに一意であり、フィールドは整数または文字列のみを受け付けます。

コレクション作成時に**AutoId**を有効にすると、Zilliz Cloud が挿入用のプライマリ値を生成します。その場合、エンティティデータにプライマリフィールドを含めないでください。

<Admonition type="info" icon="📘" title="Notes">

<p>外部コレクションはプライマリキーをサポートしておらず、AutoId 機能を使用することもできません。</p>

</Admonition>

### Refresh\{#refresh}

Refresh は外部データファイルをスキャンし、マニフェストを再生成します。通常、150～250 ms かかります。ソースデータが変更された場合は、再度 refresh を実行してコレクションを同期させてください。

<Admonition type="info" icon="📘" title="Notes">

<p>インデックスを作成する前にリフレッシュが必要なのは、外部コレクションのみです。</p>

</Admonition>

### インデックス\{#index}

インデックスは検索を高速化します。サービスが依存するすべてのフィールドにインデックスを作成し、ベクトルフィールドのインデックスは必須であることを覚えておいてください。

<Admonition type="info" icon="📘" title="Notes">

<p>外部コレクションの場合、インデックスを作成する前にリフレッシュする必要があります。</p>

</Admonition>

### エンティティ\{#entity}

エンティティはデータレコードであり、コレクション内の 1 行です。その行のすべてのフィールドがエンティティを構成します。

<Admonition type="info" icon="📘" title="Notes">

<p>外部コレクションでは、エンティティの挿入、アップサート、または削除はできません。ただし、それらの目的のためにデータをインポートすることは可能です。</p>

</Admonition>

### Load と Release\{#load-and-release}

コレクションを検索またはクエリする前に、ロードする必要があります。ロードにより、インデックスファイルと生データがメモリに取り込まれ、高速な応答が可能になります。使用していないコレクションはリリースしてコストを節約してください。

- マネージドコレクションおよびサービングクラスター内の外部コレクションの場合、Zilliz Cloud は常にインデックスファイルと生データをメモリにロードします。

- オンデマンドコンピュート内の外部コレクションの場合、Zilliz Cloud はインデックスファイルのみをロードします。

### Partition\{#partition}

パーティション はコレクションのサブセットです。同じフィールドセットを共有しますが、異なるエンティティを含みます。特定の パーティション を検索することで、Zilliz Cloud は他のすべてを無視でき、効率が向上します。

<Admonition type="info" icon="📘" title="Notes">

<p>パーティション をサポートしているのはマネージドコレクションのみです。</p>

</Admonition>

### シャード\{#shard}

シャードはコレクションの水平スライスです。各シャードはデータ入力チャネルです。デフォルトでは、すべてのコレクションに 1 つのシャードがあります。予想されるスループットとデータ量に基づいてシャード数を増やしてください。

### エイリアス\{#alias}

コレクションには複数のエイリアスを設定できますが、エイリアスをコレクション間で共有することはできません。エイリアスは、コレクション名を至る所で変更せずにコードをさまざまなシナリオに適応させる必要がある場合に役立ちます。

### 一貫性レベル\{#consistency-level}

コレクション作成時に一貫性レベルを設定するか、特定の検索またはクエリ中にそれをオーバーライドします。オプションは**Strong**、**Bounded Staleness**、**Session**、および**Eventually**です。
